## 一、设计总则

### 1.1 设计方向

平台视觉融合三重参考，但不复制任何品牌：

| 参考 | 借鉴维度 |
|------|----------|
| Runway | 媒体聚焦：暗色画布、强图片/视频预览、清晰的生成状态 |
| Linear | 项目管理密度：紧凑信息、精确状态、快速扫描、低装饰噪音 |
| VoltAgent | AI工具控制台：暗色专业底、绿色强调、技术信心 |

### 1.2 产品性格

- 专业、冷静、生产就绪
- 有创意感但不装饰
- 信息密度足够承载真实工作，但不拥挤
- 展示生成图片/视频时媒体优先
- 展示剧本/分镜/资产/剪辑/审核/交付时工作流优先

### 1.3 绝对不做

- 暖色文档助手风格
- 营销页 hero 布局
- 装饰性渐变、浮动球体、光斑
- 操作页面用超大卡片
- 单一色系主导
- 假数据/占位文本出现在生产构建中

### 1.4 工业化设计原则（v4.0 新增）

评审发现当前 UI 适合产品演示但不适合工业化生产。以下原则指导 v4.0 全部设计决策：

1. **分镜驱动生成**：所有 AI 生成（图片/视频/音频）从 Shot 触发或可关联到 Shot；生成完成先形成候选，只有用户采纳后才更新 Shot 的确切媒体版本引用与输入快照。创意工作台的自由生成是补充而非主路径。
2. **流程节点衔接**：每个生产节点完成后明确引导下一步并携带上下文（项目/Episode/Shot/资产ID），不依赖用户记忆和手动导航。
3. **权限前置**：UI 层面区分 3 种系统角色与 12 种可组合项目角色，并按命令权限键授权；系统角色不直接授予项目内容修改权。高频业务操作无权限时禁用并解释原因，安全/平台管理入口可隐藏。
4. **变更可见**：上游修改后，下游对象标记"可能过期"，展示影响范围，支持增量重生成。
5. **全链路追溯**：成片可追溯到 Shot → 资产 → 生成任务 → 模型/Prompt/参数/种子/参考图。
6. **批量优先**：核心高频操作（生成、审核、修改参数）支持批量，单人逐张操作是降级路径而非默认路径。

## 二、信息架构

### 2.1 导航分组（5组）

侧边栏从上到下分为 5 个语义组。v4.0 相比 v3.0 的变更：新增"团队与权限"独立导航项（COLLAB-02 修复）；创作工作台从顶部独立项移入创作入口组并标注项目级（AI-02 修复）。

```
顶部独立项
├── 驾驶舱          /
└── 我的待办        /todos

组一：创作入口（项目级）
├── 剧本中心        /scripts
├── 分镜导演台      /storyboards
├── 创作工作台      /studio          ← v4.0: 移入此组，标注项目级
└── AI任务队列      /ai-tasks

组二：资产工厂
├── 角色工厂        /characters
├── 场景工厂        /scenes
├── 道具工厂        /props
├── 风格库          /styles          ← 项目级 StyleAsset 生产与版本管理
└── 资产中心        /assets          ← 已授权项目资产的统一检索与复制入口

组三：AI生产与后期
├── 视频生产线      /video-production
├── 音频中心        /audio
├── 剪辑中心        /clips
└── 模型中心        /models

组四：运营管控
├── 项目中心        /projects
├── 审核中心        /review          ← v4.0: 增加个人视角 Tab
├── 质检中心        /quality
├── 发布准备        /publish
└── 数据中心        /data

组五：团队与权限（v4.0 新增）
└── 团队与权限      /projects/[id]/team  ← 项目成员与项目角色；平台用户管理位于 /admin/users
```

### 2.2 分组理由

| 分组 | 语义 | 用户心智 |
|------|------|----------|
| 创作入口 | "我今天要创作什么" | 编剧、分镜导演、创作者的日常入口 |
| 资产工厂 | "我有哪些可复用的素材" | 美术设计师、资产管理者 |
| AI生产与后期 | "怎么用AI生成和后期处理" | 视频导演、音频/剪辑人员 |
| 运营管控 | "项目怎么推进、怎么交付" | 制片人、审核人员、发布运营 |
| 团队与权限 | "谁在做什么、谁能做什么" | 项目所有者、项目管理员 |

### 2.3 资产中心与三工厂的职责边界（v4.0 新增）

评审发现资产中心与三工厂存在领域边界重叠（ASSET-01）。明确区分：

| 维度 | 三工厂 | 资产中心 |
|------|--------|----------|
| 范围 | 当前项目 | 用户有读取权限的项目集合 |
| 职责 | 角色/场景/道具/风格的生产、编辑、AI生成和项目内版本管理 | 统一搜索、浏览、来源追溯与复制复用 |
| 数据源 | 当前项目的角色/场景/道具/风格 | 仅用户有权读取的项目资产，不存在无权限“平台全库” |
| 核心操作 | CRUD + AI生成 + 一致性包 + 权利信息 | 搜索 + 组合筛选 + 复制到项目 + 反向关系查看 |
| 互相关系 | 四类工厂产出的资产进入统一检索投影 | 资产中心只复制确切已发布版本并保留来源，不创建可变跨项目引用 |

### 2.4 项目内路由结构（v4.0 新增）

评审发现 Episode 无独立路由（FLOW-02）、Shot 详情缺失（FLOW-05）。补充项目内路由层级：

```
/projects/[id]                          项目工作台（12 Tab）
/projects/[id]/episodes/[n]             Episode 工作区（v4.0 新增）
/projects/[id]/storyboards/[sid]        分镜板
/projects/[id]/shots/[shotId]           Shot 详情（v4.0 新增）
/projects/[id]/shots/[shotId]/generate  Shot 驱动的生成页面（v4.0 新增）
/projects/[id]/control-tower             Episode 生产矩阵与排产（v4.2）
/projects/[id]/continuity                连续性检查台（v4.2）
/projects/[id]/shots/[shotId]/candidates 候选比较与版本树（v4.2）
/reviews/[reviewId]/workbench            专业同步审片工作台（v4.2）
/edit-projects/[editProjectId]           多轨剪辑工程（v4.2）
```

### 2.5 页面关系

```
剧本中心 → 分镜导演台 → Shot详情 → 角色/场景/道具工厂
    ↓           ↓          ↓              ↓
  AI分析     AI拆分     生成图片/视频    AI生成
    ↓           ↓          ↓              ↓
  AI任务队列 ←←←←←←←←←←←←←←←←←←←←←←←←←←
    ↓
  视频生产线 → 音频中心 → 剪辑中心 → 审核中心 → 发布准备
                                                          ↓
                                                    全链路追溯
```

### 3.2 色彩规则

1. 强调色用于动作和状态，不用于装饰

4. 不在图片/视频预览后方放彩色背景
5. 所有硬编码 hex 值收敛到上述令牌
6. `--stale` 仅用于上游变更后标记的下游过期对象（v4.0 新增）
7. `--locked` 仅用于已冻结的生产基线对象（v4.0 新增）

## 四、页面设计

### 4.1 剧本中心 `/scripts`

**定位**: 剧本列表 + AI分析 + 审核流转入口

**布局**:

```
PageHeader (标题 + 描述)
├── StatCardGrid (4列: 总数/审核中/已通过/AI覆盖率)
├── ModuleToolbar
│   ├── left: SearchInput + 状态Filter + 集数Filter
│   └── right: AI分析 + 导入剧本 + 新建剧本(Primary)
├── Tabs (剧本列表 | 模板库 | 回收站)
└── Card
    └── Table
        ├── checkbox | 标题(+字数) | 集数 | 状态Badge | 场景数 | 角色标签 | 更新时间 | 操作
        └── Pagination
```

**设计要点**:
- 标题行显示标题 + 字数摘要（`原创剧本 · 8200字`）
- 状态使用色彩 Badge：已通过(绿) / 审核中(黄) / 草稿(灰) / 已驳回(红)
- 角色用蓝色 Badge 标签行内展示
- 操作按钮默认隐藏，hover 时显示
- 导入支持拖拽区域
- AI分析按钮可批量选中后触发

**交互**:
- 点击行 → 进入剧本编辑器（独占式）
- AI分析 → 弹窗预览分析结果（角色/场景/道具提取）
- 导入 → 拖拽弹窗，支持 .txt/.docx/.fountain/.fdx

**流程衔接（v4.0 新增 — 修复 FLOW-01）**:

AI分析完成后，不关闭弹窗而是切换到"分析结果确认"模式：
```
AI分析弹窗 → 分析进度(180s) → 完成 → 自动切换到"草稿确认"面板
├── 角色草稿列表（可编辑/删除/确认入库）
├── 场景草稿列表（可编辑/删除/确认入库）
├── 道具草稿列表（可编辑/删除/确认入库）
└── 底部: [全部入库] [逐个确认] [稍后处理]
```

- "全部入库"：一键将 AI 草稿创建为正式资产，跳转到角色工厂查看
- "逐个确认"：用户逐个审核草稿，可修改字段后入库
- "稍后处理"：草稿保留在剧本编辑器右侧面板，下次进入时提示
- 入库后角色/场景/道具工厂出现"AI分析来源"标签，关联到剧本

### 4.2 剧本编辑器 `/scripts/[id]`

**定位**: 独占式全屏编辑，三栏布局

**布局**:

```
独占式 (无侧边栏, 保留 GlobalTopBar)
├── 顶部工具栏 (bg-topbar)
│   ├── 标题 (inline-edit, 自动保存)
│   ├── 作者 + 状态下拉
│   └── 保存 / 历史 / 导入导出 / 评论
├── ScriptToolbar (格式化工具栏 + AI分析按钮)
└── 三栏
    ├── 左侧 (w-64): ScriptSidebar
    │   ├── 剧集/场景导航树
    │   └── 点击跳转 + 高亮
    ├── 中部: ScriptEditor (Tiptap) / OutlineView (大纲视图)
    └── 右侧: ScriptEditRightPanel (5 Tab)
        ├── 角色: AI提取的角色列表（v4.0: 含草稿确认状态）
        ├── 场景: AI提取的场景列表（v4.0: 含草稿确认状态）
        ├── 道具: AI提取的道具列表（v4.0: 含草稿确认状态）
        ├── AI: 分析/优化/扩写
        └── 评论: 选区评论
```

**设计要点**:
- 背景使用 `#0a0a0a`（比主背景更深，编辑器沉浸感）
- 保存状态实时显示（`已保存` / `保存中...` / `未保存`）
- AI分析结果可一键入库到角色/场景/道具工厂
- 版本历史使用 Modal + 预览对比
- 错误提示统一使用 `notify`，禁止 `alert()`

**变更影响提示（v4.0 新增 — 修复 DEP-01）**:

剧本修改保存后，若已有下游分镜/角色/场景，弹出变更影响提示：
```
┌─────────────────────────────────────────┐
│ ⚠ 剧本修改可能影响下游成果               │
│                                         │
│ 本次修改涉及 3 个场景的文本变更。        │
│ 以下下游对象可能需要更新：               │
│                                         │
│ • Episode 2: 5 个分镜可能过期            │
│ • 角色"林晓": 台词引用可能过期           │
│ • 场景"咖啡馆": 描述已变更               │
│                                         │
│ [查看影响详情]  [标记下游过期]  [忽略]   │
└─────────────────────────────────────────┘
```

- "查看影响详情"：展开影响范围列表，可逐项查看
- "标记下游过期"：下游对象的 StaleBadge 变为橙色，用户可在分镜导演台看到
- "忽略"：不标记，但记录到操作历史

### 4.3 分镜导演台 `/storyboards`

**定位**: 分镜 → 镜头 父子结构，AI拆解、资产绑定、图生视频

**布局**:

```
PageHeader
├── PipelineFlow (生产进度条: 剧本→分镜→资产→图片→视频→审核)
├── ModuleToolbar
│   ├── left: SearchInput + 状态Filter + 集数Filter + 过期Filter(v4.0)
│   └── right: AI拆分镜头 + 批量生成(Primary, v4.0) + 新增分镜
├── BatchOperationBar (v4.0: 选中后显示)
│   └── 已选 N 个分镜/镜头 → [批量生成图片] [批量生成视频] [批量修改参数] [批量审核]
└── 分镜行列表 (单列纵向)
    └── StoryboardRow
        ├── 选择复选框
        ├── 左侧编号块 (40x40, 圆角6px)
        ├── StaleBadge (v4.0: 上游变更时显示橙色"可能过期")
        ├── 右侧内容区
        │   ├── 标题 + 状态Badge + 集数Badge + 场景Badge
        │   ├── 描述 (2行截断)
        │   ├── 对白 (1行截断)
        │   └── 角色标签(蓝) + 道具标签(紫) + 资产绑定状态(v4.0)
        ├── [展开时] 镜头列表
        │   ├── AI拆分按钮 + 添加镜头按钮
        │   └── ShotRow: 编号 + 状态 + StaleBadge(v4.0) + 标题 + 时长 + 景别 + 缩略图 + 生成状态 + 操作
        └── 操作: 编辑 / Shot详情(v4.0) / 图生视频(Primary) / 展开(N) / 删除
```

**设计要点**:
- 单列纵向时间轴，强调叙事顺序
- PipelineFlow 顶部显示，让用户知道当前在哪个阶段
- 展开状态使用 localStorage 持久化（按 projectId 隔离）
- 选中分镜后显示批量操作条，支持批量生成图片/视频（v4.0 修复 EFF-01）
- 镜头缩略图保持原始比例（9:16竖版不拉伸）
- 操作按钮 hover 显示，但保留至少 1-2 个高频按钮默认可见
- StaleBadge 在上游变更时自动显示，点击可查看变更原因（v4.0 修复 DEP-03）

**资产绑定交互（v4.0 新增 — 修复 FLOW-04）**:

分镜行展开后，每个 Shot 可绑定角色/场景/道具资产：
```
ShotRow 展开编辑模式:
```

- `DelegationPanel` 展示权限范围和起止时间；owner 转移、平台凭据等不可委托能力不出现。
- 成员移除/代理到期时，控制塔显示待移交项并支持批量转交，历史署名保留。

**三种 fallback 模式**:

| 模式 | 行为 | 适用场景 |
|------|------|----------|

### 5.14 TraceabilityChain 追溯链（v4.0 新增）

从任一候选、审核快照或成片向上/向下展开的完整证据链。

```

 └── RenderArtifact(hash) → EditProject revision
     └── Clip / Audio version / Subtitle version
         └── adopted media version → AITask execution snapshot
             └── Shot PresentationSnapshot
                 └── Script / Character / Scene / Prop / StyleAsset exact versions + rights snapshot
```

**设计要点**:
- 树形结构，可展开/折叠
- 每个节点显示：类型、名称、确切版本/哈希、时间和权限状态；AI 节点展示 Provider/模型版本/Prompt 版本或哈希/参数/seed/参考媒体/尝试/成本

- 断链节点红色标记缺失证据类型；顶部显示 `complete/partial/rebuilding`、投影水位和完整性哈希
- 点击节点跳转到对应详情页
- 支持导出 JSON/PDF；导出前显示范围与脱敏规则，结果带生成时间、水位和完整性哈希并写审计
- 追溯链在 Shot、资产、AI任务、剪辑工程和成片详情页展示

### 6.2 状态设计

不同聚合使用各自领域状态机，UI 不定义一套可写的“所有对象标准状态”。以下只是一组展示语义映射；`DependencyFreshness` 与 `locked/frozen` 是叠加标记，不进入对象状态转换控件：

| 状态 | Badge | 色 | 下一步 |
|------|-------|-----|--------|
| Ready 已就绪 | success | 绿 | 可用于下游 |
| Incomplete 待完善 | warning | 黄 | 补充信息 |
| Processing 处理中 | info | 蓝 | 等待完成 |
| Review 审核中 | warning | 黄 | 等待审核结果 |
| Done 完成 | success | 绿 | 进入下一阶段 |
| Failed 失败 | error | 红 | 查看原因并重试 |
| Potentially stale / stale | dependencyFreshness | 橙/红 | 查看影响、保持确切旧版本或创建升级计划 |
| Blocked | dependencyFreshness | 深红 | 修复权利/版本/证据阻断，不允许发布 |
| Locked/Frozen | overlay flag | 紫 | 展示已冻结版本或快照；不冒充生命周期状态 |

### 6.5 分页与虚拟滚动

所有列表/网格页面统一使用分页组件或虚拟滚动。

**分页组件结构**:

```
左: 共 X 条 · 每页 [10/20/50] 条    右: [上一页] [1] [2] [3] ... [n] [下一页]
```

**分页规则**:
- 默认每页 10 条（表格）/ 12 条（卡片网格），用户可切换 10/20/50
- 页码超过 7 页时显示省略号 `...`
- 当前页高亮 `accent-dim` 背景
- 首页禁用"上一页"，末页禁用"下一页"
- 选中可跨页保留（checkbox 状态持久化）
- 切换页码时不触发页面跳转，仅替换列表内容
- 搜索/筛选后自动回到第 1 页

**虚拟滚动（v4.0 新增 — 修复 EFF-11）**:

需求 V1 目标 10000 分镜 / 50000 图片，分页不够。大数据量页面引入虚拟滚动：
- 分镜列表 > 500 条时自动切换虚拟滚动
- 资产网格 > 1000 条时自动切换虚拟滚动
- 使用 `@tanstack/react-virtual` 实现
- 虚拟滚动时保持选中状态和筛选条件

**需要分页/虚拟滚动的页面**: 剧本中心、分镜导演台、角色工厂、场景工厂、道具工厂、视频生产线任务队列、音频中心、剪辑中心片段列表、AI任务队列、我的待办、资产中心

### 6.9 变更影响提示（v4.0 新增 — 修复 DEP 系列）

**触发时机**:
- 剧本保存后（影响分镜/角色/场景）
- 角色/场景资产保存后（影响分镜/图片/视频）
- 分镜修改后（影响图片/视频/音频）

**提示方式**:
- 修改保存成功后，弹出 ChangeImpactDialog
- 对话框展示影响范围列表
- 用户选择处理方式：标记过期 / 增量重生成 / 忽略
- 标记过期的对象在所有页面显示 StaleBadge

**增量重生成**:
- 仅重新生成标记为"可能过期"的内容
- 保留未受影响的生成结果
- 批量提交重生成任务到任务队列

### 6.10 网络与容错（v4.0 新增 — 修复 UX 系列）

**网络中断处理**:
- 检测到网络断开时，全局顶部显示橙色横幅："网络已断开，正在重连..."
- 自动重连（指数退避，最多 5 次）
- 重连成功后自动刷新当前页面数据
- 编辑中的表单内容保留，不丢失

**防重复提交**:
- 所有生成/发布/提交按钮点击后立即禁用 + Loading
- 按钮恢复条件：服务端响应 或 30秒超时
- 超时后提示"操作超时，请检查任务队列确认结果"

**浏览器关闭保护**:
- 有未保存内容时，`beforeunload` 事件提示
- 编辑内容每 10 秒自动保存草稿到 sessionStorage
- 重新打开时恢复草稿

**批量操作部分失败**:
- 批量操作结果以列表形式展示：成功项(绿) + 失败项(红) + 原因
- 支持"仅重试失败项"
- 失败项保留原始输入参数

---

### 6.11 并发、草稿与恢复（v4.2）

| 场景 | UI 行为 | 禁止行为 |
|---|---|---|
| 其他成员持有租约 | 默认只读，显示持有人和到期；允许评论 | 伪装为可编辑后在保存时才报错 |
| 租约在编辑中失效 | 保留本地草稿、停止服务端保存、提供重新申请 | 清空画布或自动覆盖新持有人内容 |
| expectedVersion 冲突 | 打开差异对话框，允许重应用/另存/放弃 | 最后写入者自动获胜 |
| 自动保存失败 | 持续错误状态 + 本地恢复点 + 重试 | 短暂 toast 后显示“已保存” |
| 离线恢复 | 重新校验权限、租约、父对象、版本和权利 | 直接把离线草稿覆盖到当前版本 |
| 强制接管 | 显示未保存风险，要求原因，通知原持有人 | 无审计静默抢锁 |

批量操作、审核决定、候选采纳和时间线保存均必须携带 idempotencyKey/expectedVersion；前端只能展示服务端逐项结果，不能根据本地乐观结果提前改成终态。

## 七、媒体规则

### 7.1 图片展示

| 场景 | 方式 |
|------|------|
| 缩略图列表 | `object-cover`（裁剪可接受） |
| 详情/预览 | `object-contain`（保持比例） |
| 9:16竖版 | 显示为竖版，不拉伸 |
| 16:9横版 | 显示为横版 |
| 多结果比较 | 并排展示，保持比例（v4.0 新增） |

### 7.2 视频展示

- 预览需要可见的控制条
- 显示时长/状态
- 提供下载/打开操作
- 生成中的视频显示进度条

### 7.3 媒体绑定

- 生成媒体先绑定为 Shot/资产的候选版本；任务完成不得自动覆盖当前采纳版本
- 采纳后保存不可变媒体版本 ID、生成输入/表现快照哈希和 AI 执行快照哈希；URL 仅用于展示，不作为业务引用
- 删除/归档对话不得级联删除已被任务、候选、Shot、审核、剪辑或成片引用的媒体和执行证据；只解除会话展示关系
- 存储位置可以是本地或对象存储，需求只约束稳定媒体 ID、内容哈希、访问控制和生命周期，不限定技术实现
- 执行快照完整记录 Provider、模型版本、Prompt 模板版本或文本哈希、参数、seed、参考媒体版本、任务尝试和成本；敏感凭据不得写入

## 九、实施规则

### 9.1 技术约束

- 使用现有 Tailwind 模式
- 不使用图标库，按钮和导航项使用纯文字
- 禁止引入新视觉库（除非有明确需求）
- 禁止 inline `style={}` 硬编码颜色
- 禁止 `alert()` / `window.confirm()`
- 所有 API 调用走 `lib/api-client`
- 所有 fetch 使用 `api()` 方法
- 模型名称从 ModelConfig 动态加载，禁止写死（v4.0 新增）
- 权限检查使用 PermissionGuard 组件包裹（v4.0 新增）
- 大数据量列表使用虚拟滚动（v4.0 新增）

### 9.2 色彩收敛

将现有3种色彩使用方式统一:

| 当前方式 | 目标 |
|----------|------|
| `bg-emerald-500/10` (Tailwind) | 保留 |
| `bg-[#202020]` (任意值) | 收敛到 CSS 变量 `--bg-card` |
| `rgba(255,255,255,0.10)` (inline) | 收敛到 `--border` |

### 9.3 完成检查

```bat
cd frontend
npm run build
```

构建通过后检查:
- [ ] 无硬编码颜色字面量
- [ ] 无 `alert()` / `window.confirm()`
- [ ] 无假数据/占位文字
- [ ] 空状态有引导文案
- [ ] 列表页有分页组件或虚拟滚动
- [ ] 无图标，按钮均为文字
- [ ] 生成结果先形成候选，采纳后绑定候选 ID、确切媒体版本与快照，未写可变 URL/任务 ID
- [ ] 模型名称从 ModelConfig 加载（v4.0 新增）
- [ ] 权限控制使用 PermissionGuard（v4.0 新增）
- [ ] 上游变更后显示 StaleBadge（v4.0 新增）
- [ ] 批量操作显示影响范围（v4.0 新增）
- [ ] 生产矩阵的实际完成量只读并显示投影水位
- [ ] 核心编辑页显示租约、expectedVersion、自动保存和冲突恢复状态
- [ ] 候选、连续性、批注和时间线均引用确切版本
- [ ] 专业工作台覆盖正常、部分失败、断网、租约失效和版本冲突
