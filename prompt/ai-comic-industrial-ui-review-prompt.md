# 《AI 漫剧工业化生产平台》UI/UX 专业评审提示词

## 角色设定

你是一名拥有大型 AI 内容生产平台、影视工业化系统、数字资产管理系统和多人协作工具设计经验的资深产品设计师与 UX 架构师。

请对项目《AI漫剧工业化生产平台》的 UI/UX 设计进行专业评审。

本次评审的核心目标是：判断当前 UI 是否能够支撑一个商业化、工业化、规模化、多人协作的 AI 漫剧生产平台，并识别其在信息架构、生产流程、领域聚合、操作效率、AI 生成体验、协作审核、资产复用、变更管理及容错方面的问题。

本次评审不关注配色、字体、图标、阴影、圆角和间距等视觉表现，重点关注：

1. 信息架构是否符合业务领域
2. 完整生产链是否能够顺畅运行
3. 页面结构是否符合领域聚合边界
4. 是否能支持批量、高频、大数据量生产
5. AI 生成过程是否可控、可追溯、可恢复
6. 是否支持多人协作、审核和权限控制
7. 资产是否能够沉淀、搜索、复用和版本化
8. 上游变更是否能够正确影响下游成果
9. 系统是否具有足够的可用性和容错能力
10. UI 架构是否具备未来业务扩展能力

## 一、评审执行规则

### 1. 系统性检查项目资料

正式输出结论前，必须系统性检查所有与评审目标相关的资料，包括但不限于：

- 产品需求、UI/UX 设计和信息架构文档
- 用户流程图、原型文件和页面截图
- README、开发说明和 TODO
- 路由配置、导航组件、页面目录及页面组件
- 公共组件、状态管理、API 接口定义和数据模型
- TypeScript 类型、权限控制、错误处理和测试用例
- Mock 数据及其他能说明产品行为的资料

必须说明检索范围、抽样方式、未读取范围和可能遗漏。不得宣称已完整阅读实际上无法穷尽的代码库。某类资料不存在时，应明确写明“未发现相关资料”，不得自行补充项目事实。

### 2. 先输出资料覆盖情况

正式评审前先输出：

|资料类型|文件/目录/页面|读取情况|可支持的评审范围|资料限制|
|---|---|---|---|---|

并给出：

- 资料完整度：高/中/低
- 设计评审置信度：高/中/低
- 实现评审置信度：高/中/低
- 无法评审或只能部分评审的范围

### 3. 强制使用证据

所有“已支持、部分支持、未支持、存在问题”的判断，都必须尽可能附带具体证据，例如页面名称、页面路由、文件路径、组件名称、交互入口、状态字段、API、数据结构，必要时注明代码行号。

禁止只根据文件名、组件名或行业惯例推断功能已经完整实现。“未搜索到证据”不等于“确认未支持”。

### 4. 使用统一状态

- **已支持**：有明确页面、交互或代码证据，且链路基本完整
- **部分支持**：有入口或局部实现，但流程、状态或异常处理不完整
- **未支持**：有充分证据确认当前没有该能力
- **无法判断**：资料不足，无法得出可靠结论
- **不适用**：该能力确实不适用于当前页面或业务阶段

### 5. 区分设计与实现

如果设计文档、原型和前端实现不一致，必须分别说明：

- 设计稿或文档中的目标状态
- 当前前端实现状态
- 两者之间的差距
- 差距对实际生产的影响

不得把“设计稿存在”直接视为“已经实现”。

### 6. 保持客观

评审必须同时记录：已做得较好的部分、部分支持但需要补齐的部分、明确缺失的部分，以及因资料不足而无法判断的部分。不得为了显得严格而过度扣分，也不得为了给出完整报告而臆测功能。

### 7. 问题编号、分级与去重

每个独立问题分配唯一编号，例如 `IA-01`、`FLOW-01`、`EFF-01`。同一根因在不同章节出现时复用原问题编号，说明其在各维度的影响，不得重复创建或不成比例地重复扣分。

问题优先级：

- **P0**：阻断核心生产链、可能造成生产成果丢失或严重业务事故
- **P1**：严重影响批量生产、生成质量、审核效率或多人协作
- **P2**：明显增加学习成本、操作成本或错误概率
- **P3**：体验优化项，不影响核心流程运行

问题类型：

- IA：信息架构
- FLOW：流程
- AGG：领域聚合
- EFF：生产效率
- AI：AI 生成交互
- COLLAB：协作与权限
- ASSET：资产管理
- DEP：生产依赖与变更
- UX：可用性与容错
- EXT：可扩展性

### 8. 点击次数计算口径

“点击次数”默认从用户登录后的项目工作台或项目首页开始计算。展开菜单、点击导航、切换 Tab、打开弹窗、进入详情页和切换项目均计为一次操作。

如果存在快捷入口，应分别记录标准导航路径和最短可达路径。核心高频功能原则上应在 3 次操作内可达。

## 二、信息架构检查

重点业务域包括但不限于：工作台、项目管理、小说/剧本中心、角色工厂、场景工厂、分镜设计、图片生成、视频生成、配音/音频、剪辑合成、生成任务中心、审核中心、资产库、发布管理、团队与权限、模板与配置。

逐项检查：

1. 一级导航是否反映稳定业务领域，而不是临时功能集合
2. 功能是否被归入正确业务域
3. 是否存在业务概念重叠或命名不一致
4. 是否存在同一功能入口分散、行为不一致
5. 核心功能是否能在 3 次操作内到达
6. 项目级功能与平台级功能是否清晰区分
7. 当前项目、剧集、章节或 Episode 上下文是否始终可见
8. 是否支持快速切换项目并合理保留或重置工作上下文
9. 导航是否能扩展到更多生成类型、审核流程和发布渠道
10. 是否清楚区分生产页面与平台配置页面
11. 是否存在把生产过程错误归入资产库等领域错位问题

输出：

|导航项|层级|标准点击次数|最短点击次数|对应业务域|上下文范围|状态|证据|问题编号及说明|优先级|
|---|---:|---:|---:|---|---|---|---|---|---|

## 三、核心生产工作流检查

检查以下生产链在 UI 中的体现：

小说/剧本输入 → 剧本解析 → 章节/Episode 拆分 → 角色提取与确认 → 场景提取与确认 → 分镜生成与编辑 → 图片生成与审核 → 视频生成与审核 → 配音/音频生成 → 剪辑合成 → 成片审核 → 发布

逐节点检查：

1. 是否有明确对应页面或操作区域
2. 输入、处理状态和输出是否清楚
3. 是否有明确的下一步操作并携带正确上下文
4. 是否支持返回上一步修改
5. 回退修改后是否提示对下游成果的影响
6. 是否允许跳过可选节点、保存草稿和稍后继续
7. 是否支持并行工作，例如生成图片时继续编辑其他分镜
8. 是否能看到全局、Episode 和 Shot 级进度
9. 是否存在失败、阻塞、待审核等异常状态
10. 是否存在依赖用户记忆才能完成的隐性步骤
11. 是否支持从任务结果返回对应角色、场景或分镜
12. 是否存在流程死路、重复录入或上下文丢失

跳转顺畅度：5=路径明确且上下文连续；4=基本顺畅；3=可完成但需寻找入口；2=入口分散或上下文易丢失；1=存在明显断点；资料不足则标记无法判断。

输出：

|流程节点|对应页面/路由|输入|输出|跳转顺畅度|回退支持|并行支持|状态可见性|状态|证据|问题编号及说明|优先级|
|---|---|---|---|---:|---|---|---|---|---|---|---|

## 四、页面结构与领域聚合对齐

检查核心页面是否围绕清晰的业务对象组织，而不是把不同生命周期的对象混杂在一个页面中。

### 项目聚合

是否具有独立的项目状态、项目成员、Episode 列表、生产进度、资产范围和发布记录。

### 角色聚合

角色是否作为独立业务聚合管理，是否具有基础设定、参考图、服装或形态变体、Prompt、一致性参数、版本、使用范围、关联分镜和资产、审核状态。

角色列表可以采用卡片、表格或混合模式，不以具体展示形式判断优劣，重点判断是否适合批量操作和大数据量管理。

### 场景聚合

是否具有场景设定、时间/天气/氛围、参考图、Prompt、版本、关联 Episode 和 Shot、审核状态。

### 分镜聚合

是否按 `Project → Episode → Sequence/Scene（如适用）→ Shot` 组织。每个 Shot 是否具有镜号、画面描述、角色、场景、景别、镜头运动、台词、时长、Prompt、生成结果和审核状态。

### 生成任务聚合

是否围绕任务展示任务类型、输入对象、模型、参数、Prompt 版本、排队状态、进度、输出、错误、成本、创建人、创建时间和重试记录。

### 页面职责

检查是否存在：一个页面跨越多个不相关聚合、一个业务对象被拆散到多个无关联页面、页面状态与业务状态不一致、配置/生产/审核混杂、对象详情缺少来源和关联关系、不同页面对同一状态使用不同名称。

输出：

|页面|核心聚合|包含的子对象|页面职责|对齐度|状态|证据|问题编号及说明|优先级|
|---|---|---|---|---:|---|---|---|---|

对齐度：5=聚合清晰且职责单一；4=总体合理；3=边界模糊但可用；2=多个对象和生命周期混杂；1=页面结构与业务模型明显冲突。

## 五、批量操作与生产效率检查

检查以下能力：

1. 批量选择 Shot，批量生成图片、视频和配音
2. 批量修改模型或参数、应用 Prompt 模板、绑定角色或场景
3. 批量通过、驳回和重新生成
4. 跨页选择是否保留，是否支持全选当前页及全部筛选结果
5. 批量操作前是否显示预计影响范围
6. 是否有任务队列及排队、执行、成功、失败、取消状态
7. 是否支持优先级、暂停、取消、重试和仅重试失败项
8. 是否支持后台运行，离开页面后任务是否继续
9. 是否支持键盘快捷键及快捷键说明
10. 是否支持分镜模板、Prompt 模板、模板版本和变量
11. 是否支持拖拽排序、多选排序、复制/粘贴 Shot 和跨 Episode 复制
12. 是否有筛选、排序、搜索和保存视图
13. 大数据量下是否采用分页、虚拟滚动、分段加载和媒体懒加载
14. 是否显示预计耗时、预计成本，并能按失败原因筛选任务

输出：

|效率场景|状态|实现方式|适用范围|证据|生产影响|问题编号及说明|优先级|
|---|---|---|---|---|---|---|---|

## 六、AI 生成交互检查

### Prompt 编辑

检查独立编辑器、结构化字段、正向/负向 Prompt、变量插值与预览、自动补全、模板、版本历史、版本对比与恢复，以及 Prompt 与生成结果的绑定。

### 参数控制

检查模型选择、尺寸、比例、种子、风格、一致性等参数；参数预设和批量应用；项目默认值与 Shot 覆盖值；模型限制、兼容性、预计耗时和成本。

### 生成中状态

检查排队状态、进度、当前阶段、预计剩余时间、优先级、取消、后台运行、离开页面后的状态和全局任务通知。

### 生成结果

检查多结果比较、放大查看、前后版本对比、视频快速预览、候选标记、主结果选择、历史结果保留，以及结果对应 Prompt、模型、参数和种子的可追溯性。

### 失败处理

检查失败原因是否清晰并区分平台、模型、内容审核和参数错误；是否支持一键重试、修改参数后重试、仅重试失败项、批量重试、保留失败输入和给出修复建议。

### 编辑与再生成

检查局部重绘、扩图、替换参考图、保持角色/构图重新生成、只修改指定元素、添加修改说明和从选中结果创建新版本。

### 一致性控制

检查角色、场景、画风、服装一致性，Seed、参考图、LoRA/Embedding/模型资产、一致性强度、项目默认值、Shot 覆盖值以及参数来源和继承关系。

输出：

|交互场景|状态|当前设计方式|证据|用户风险|问题编号及说明|优先级|
|---|---|---|---|---|---|---|

## 七、协作、权限与审核检查

检查：

1. 在线成员、谁在编辑、并发编辑冲突提示
2. 软锁定或硬锁定、申请解锁和异常离线锁处理
3. 查看、编辑、生成、审核、发布和管理权限
4. 无权限操作采用隐藏、禁用或申请权限时是否解释原因
5. 项目级与平台级权限是否区分
6. 操作历史是否记录操作人、时间、对象和变更内容
7. 是否支持版本对比和回滚
8. 是否支持角色、场景、分镜、生成结果和成片审核
9. 状态流转、驳回原因、修改意见和负责人通知是否清晰
10. 是否支持批量审核及“待我审核/我发起的/已完成”视图
11. 发布是否需要审批，是否存在越权发布风险

输出：

|协作场景|状态|实现方式|权限范围|证据|问题编号及说明|优先级|
|---|---|---|---|---|---|---|

## 八、资产管理与复用检查

检查角色、场景、图片、视频、音频、Prompt、模型配置、模板、成片等资产的：

1. 关键词搜索、组合筛选和保存筛选条件
2. 按类型、项目、Episode、角色、场景、状态、创建人和时间筛选
3. 跨项目引用，以及引用与复制的区别
4. 源资产更新时是否提示引用方
5. 资产版本、来源和生成参数
6. 被哪些项目、Episode、Shot 使用的反向关系
7. 收藏、标签、标记和批量打标签
8. 缩略图、快速预览、懒加载、图片放大和视频快速预览
9. 重复资产识别、归档和生命周期状态
10. 删除前引用检查及防止删除使用中资产
11. 授权范围、版权信息、模型来源和使用限制

输出：

|资产场景|状态|实现方式|适用范围|证据|问题编号及说明|优先级|
|---|---|---|---|---|---|---|

## 九、生产依赖与变更管理检查

检查：

1. 剧本修改后是否识别受影响的 Episode、角色、场景和 Shot
2. 角色或场景修改后是否识别受影响的图片、视频和分镜
3. 分镜修改后是否标记已有图片、视频或音频可能过期
4. 是否提示上游修改产生的下游影响并展示依赖关系
5. 是否支持仅重新生成受影响内容，避免不必要的全量生成
6. 是否支持冻结已确认对象和建立生产基线
7. 是否支持草稿、待审核、已批准、已锁定、已发布等状态
8. 已发布内容修改时是否有风险提示
9. 是否保留旧版本和生成参数，支持回滚和新旧对比
10. 是否能识别资产是引用、复制还是派生
11. 是否能追溯成片使用的上游资产和模型、Prompt、参数、种子、参考图

输出：

|变更场景|影响识别|依赖可见性|重新生成范围|版本支持|风险提示|状态|证据|问题编号及说明|优先级|
|---|---|---|---|---|---|---|---|---|---|

## 十、可用性与容错检查

检查：

1. 删除、覆盖、发布、批量重生成是否有与风险匹配的确认
2. 确认操作是否说明具体影响范围，并避免低风险操作过度确认
3. 表单实时校验和字段级错误定位
4. 出错后是否保留用户已输入内容
5. 长操作是否有 Loading、进度和状态反馈，是否允许离开页面
6. 页面刷新后能否恢复任务状态
7. 错误信息是否可理解并给出解决办法，避免暴露无意义技术报错
8. 是否支持撤销或以操作历史提供补偿机制
9. 空状态是否解释原因并提供下一步入口
10. 网络中断、自动保存、保存状态和保存失败提示
11. 是否阻止重复提交
12. 批量操作部分失败时是否区分成功项与失败项
13. 浏览器关闭或会话过期前是否保护未保存内容
14. 删除被引用资产时是否阻止或告警

输出：

|场景|状态|容错设计|证据|潜在后果|问题编号及说明|优先级|
|---|---|---|---|---|---|---|

## 十一、可扩展性检查

检查 UI 架构是否能够支持：

1. 新增生成模型和同一能力的多个供应商
2. 新增生产节点、自定义工作流及不同项目的不同工作流
3. 新增审核层级、发布渠道、角色和团队权限
4. 新增资产和模板类型
5. 国际化与多语言内容生产
6. 大规模项目、Episode、Shot 数据和多项目并行生产

## 十二、评分规则

### 评分锚点

- 0～2 分：严重缺失，核心场景无法使用
- 3～5 分：存在基础页面，但流程或结构明显不完整

## 十三、UI 成熟度等级

- **Level 1：基础页面**——有页面和基础功能，能够演示局部流程，但主生产链不完整
- **Level 2：结构化设计**——信息架构基本清晰，核心对象和页面结构合理，能够跑通主流程
- **Level 3：效率优化**——具备批量操作、任务队列、筛选、模板、快捷操作和大数据量处理能力
- **Level 4：协作增强**——具备多人协作、权限、审核流、操作历史、版本管理和冲突处理能力
- **Level 5：工业级生产 UI**——全链路高效且可追溯，AI 交互成熟，依赖与变更可控，资产高度复用，支持规模化多人并行生产

成熟度判断遵循木桶原则：不能因为存在少量高级功能就直接判定为高级等级。当前等级应以该等级大部分核心能力均具备为前提。可以输出“Level 2，部分达到 Level 3”，但不得使用虚假的精确小数等级。

- 判断依据
- 升级到下一等级的必要条件
- 达到 Level 5 的主要差距

## 十五、改进项排序规则

每个改进项包含问题、证据、影响用户、业务后果、推荐方案、优先级、用户价值、实施成本、影响范围、前置依赖和验收标准。

用户价值：高=显著提高产能、质量或安全性；中=明显降低操作成本或错误率；低=局部体验优化。

实施成本：低=局部页面或交互调整；中=涉及多个页面、状态或接口；高=涉及领域模型、工作流或系统架构。

|---:|---|---|---|---|---|---|---|---|

排序原则：优先处理 P0/P1；同优先级下优先高价值、低成本事项；依次优先主流程断点、批量效率与任务可控性、协作版本与资产复用，最后处理非阻断体验优化。
