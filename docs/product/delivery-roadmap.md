# 产品交付路线图与门禁

> **原则**：这是正式产品的交付路线，不使用“先做一个能跑的 MVP”作为完成标准。允许分阶段交付，但每个对外承诺的能力都必须满足完整产品门禁。

## 1. 优先级定义

| 等级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 首个正式发布阻断项；缺失会破坏核心价值、数据、权限、成本、质量或恢复能力 | 未关闭不得发布 |
| P1 | 已承诺的正式产品能力；可按版本分批交付，但进入某版本后必须完整验收 | 未完成不得宣称该版本支持 |
| P2 | 增强体验或效率，不影响已承诺流程的正确性与可恢复性 | 可进入后续版本 |
| S | 战略候选能力 | 产品决策前不得进入开发排期 |

## 2. 五道交付门禁

### 当前门禁状态（2026-07-28）

| 门禁 | 文档状态 | 实现/发布状态 |
|---|---|---|
| Gate 0 产品决策 | 已完成：PD-001～007 冻结 | 不适用 |
| Gate 1 需求与旅程 | 已完成：MANGA-001～008、US-022～029、J-00～07、RBAC 已定义 | 待产品/安全/岗位实测验证 |

### Gate 0：产品决策冻结

**目标**：团队对“做什么、为谁做、什么不做”达成一致。

退出条件：

- PD-001～PD-007 已确认并记录决策人、日期和理由。
- 目标用户、主制品、画幅/渠道、部署与身份接入范围明确。
- 产品成功指标有口径，目标值可后续校准。
- 不再使用 MVP 作为需求降格理由。

### Gate 1：需求与用户旅程冻结

**目标**：每个承诺能力都有完整的用户视角和异常闭环。

退出条件：

- 漫剧专业需求进入正式 US/AC。
- J-00～J-07 映射到页面、通知、命令和验收用例。
- 认证、通知、配置、审计、回收站、导入导出和备份形成平台级用户故事。
- 命令级权限矩阵由产品、安全和岗位负责人签署。
- 所有 P0 需求覆盖正常、异常、取消、超时、重试、恢复和越权场景。

### Gate 2：领域与接口契约冻结

**目标**：消除文档、领域、API 和数据模型的冲突。

退出条件：

- Shot 表现模型及 Shot–Storyboard 事务边界冻结。
- 系统角色/项目角色、通知、设置、审计和回收站边界冻结。
- 字符串错误码、HTTP status 和响应 envelope 统一。
- Outbox/Inbox/DLQ/投影位点及事件 schema 版本规则冻结。
- OpenAPI 可生成并具有漂移门禁。
- Audio/project_clips 迁移方案和回滚方案通过评审。

### Gate 3：实现与证据闭环

**目标**：设计成为真实、可验证的产品能力。

退出条件：

- 每个 P0 追踪项均有代码、API、Schema、迁移、自动化测试和监控证据。
- 正常、负向、权限、并发、幂等、超时、恢复 E2E 通过。
- 核心领域测试覆盖率达到团队门禁，且不以低价值行覆盖率替代场景覆盖。
- 数据迁移完成试跑、核对和回滚演练。
- `feature-status.md` 由“未核验”按证据逐项更新。

### Gate 4：正式发布准备

**目标**：产品可以安全运营、升级和恢复。

退出条件：

- 安全、内容合规、字体/素材版权和隐私检查通过。
- 预算、质量、审核、通知和发布 SLA 监控可用。
- 备份恢复、Provider 故障、队列积压、事件重放和发布回滚完成演练。
- 发布说明只列出已验收能力和已知限制。
- 产品、开发、测试、运维共同签署发布范围。

## 3. 工作流顺序

| 顺序 | 工作流 | 核心产出 | 依赖 |
|---:|---|---|---|
| 1 | 产品范围与漫剧差异化 | 决策清单、专业 US/AC、产品指标 | Gate 0 |
| 2 | 用户旅程与信息架构 | 角色入口、任务交接、异常旅程 | 1 |
| 3 | 权限与核心契约 | RBAC、错误、事务、事件、API | 1-2 |
| 4 | 主生产链路整改 | Script→Asset→Storyboard→Generation→Review | 3 |
| 5 | 后期与发布链路 | Audio/Subtitle/Edit/Render/FinalReview/Publish | 3-4 |
| 6 | 运营支撑 | Notification/Settings/Audit/Trash/Backup | 3，可与4-5并行实施 |
| 7 | 数据迁移与发布准备 | 迁移核对、恢复演练、功能状态证据 | 4-6 |

## 6. 禁止用作“完成”证据的情况

- 页面、按钮或演示数据存在。
- 只有接口定义，没有持久化和错误路径。
- 只有单元测试，没有跨模块旅程验收。
- 只有新数据可用，没有历史数据迁移。
- 只有管理员路径可用，普通岗位权限未验证。
- 只有成功路径，没有取消、超时、重试和恢复。
- 文档写明“支持”，但 `feature-status.md` 仍为未核验。
