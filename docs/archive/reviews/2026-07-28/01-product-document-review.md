# 产品级文档 Review 报告（2026-07-28）

> **Review 范围**：产品决策、需求、用户旅程、RBAC、DDD、错误契约、通知、成本质量、发布、数据生命周期、迁移、索引与追踪关系。  
> **结论**：文档层 Gate 0、Gate 1 已完成；Gate 2 的目标契约已完整定义。当前未发现已知的文档级发布阻断矛盾。代码、OpenAPI、Schema、迁移执行和自动化验收仍为待核验，不能由本报告替代。

## 1. Review 方法

1. 从目标用户与主制品反向检查需求是否表达动态漫剧差异化。
2. 从 J-00～J-07 检查每次岗位交接、异常、恢复、通知和审计。
3. 从每个 P0/P1 需求检查领域对象、命令、事件、API/Schema 目标和验收证据位置。
4. 对跨文档术语、上下文数量、角色、状态、错误码和事件消费者进行全文检索。
5. 对相对链接、Markdown 表格、UTF-8 和 Git diff 空白错误进行自动检查。

## 2. 第一轮发现与修复

| 发现 | 风险 | 修复 |
|---|---|---|
| 正式产品与“MVP核心”口径并存 | 团队会以主路径可用降格验收 | P0/P1/P2 改为正式发布阻断/承诺/增强，并建立 Gate 0～4 |
| 动态漫剧仅有通用 Shot 字段 | 产品缺乏专业壁垒且无法验收 | 增加 MANGA-001～008、CompositionSpec、VisualLayer、TextOverlay、ComicEffectCue、MotionCue、PresentationSnapshot |
| Shot/Storyboard AddShot 无事务 | 孤儿 Shot、引用丢失、重复创建 | 定义 UnitOfWork、版本、锁顺序、幂等、Outbox 和未来 Saga 前提 |
| 通知与智能助手混杂 | WorkItem 和投递职责混乱 | 新增 §3.10 通知上下文；WorkItem 负责处置，Notification 负责触达 |
| 新增上下文后仍有“9个上下文”残留 | 索引与权威引用错误 | 全量统一为 10，并补上下文/模块/治理索引 |
| 页面数量 23/26 冲突 | 不稳定数字被误当契约 | 删除固定页数，统一以 module-map 为准 |
| 领域字符串码与数字业务码并存 | 前端两套分支、消息文本推断状态 | 冻结字符串 error.code、HTTP、retryable、traceId 和 legacyCode 退役 |
| Audio 旧聚合仍保留完整命令/事件 | 新开发继续扩展错误模型 | 从活动 DDD 删除旧命令/事件，只保留迁移指针 |

## 3. 第二轮发现与修复

| 发现 | 风险 | 修复 |
|---|---|---|
| 只写生产旅程，没有入组/首次登录旅程 | 身份、角色和通知偏好无法验收 | 增加 J-00 加入组织与首次进入项目 |
| 项目 `permissions[]` 不能表达拒绝 | 多角色并集无法收回高风险权限 | 改为 permissionOverrides.allow/deny，deny 优先 |
| owner/admin 审核权限可能绕过职责分离 | 自审、两级审核同人 | RBAC 标为条件审批；Review 增加本人作品限制与两级审核人分离 |
| 生成只冻结 Prompt/资产 | 构图、文字、特效改变后回调污染新版本 | 生成输入增加表现结构哈希；回调必须关联输入哈希 |
| 后期只引用 Shot 视频 URL/版本 | 无法复现画面表现 | VideoClip 必须引用 Shot 视频版本 + PresentationSnapshot |
| 预算只有检查/记账 | 并发穿透、失败不释放、无法对账 | 增加 BudgetReservation、预占/结算/释放/过期和每日对账 |
| QC 只有结果对象 | 规则不可配置/版本化，超时永久 running | 增加 QualityRuleSet、deadline、timed_out、重试和人工接管 |
| 发布直接重试未知结果 | 平台已成功时可能重复发布 | 增加 adapter、providerRequestId、unknown_result 对账和批次隔离 |
| Audio/Clip 迁移仅一句 TODO | 无法切换和回滚 | 增加字段映射、Inventory/Backfill/Shadow/Cutover/Contract、核对与 journal 回滚 |
| 认证/通知/配置/审计等被误判“完全缺失” | 重复建设或忽略产品化缺口 | 区分局部实现与需求缺口，形成 US-022～029 完整验收附件 |
| 数据流图仍将失败告警投递给智能助手 | 通知上下文拆分后职责仍不一致 | 将失败告警统一路由到通知中心，需处置的事件再独立创建 WorkItem |
| 指南示例仍返回 `code: 0` | 新旧响应契约继续扩散 | 改为 HTTP 2xx + `data`，错误统一使用字符串 `error.code` |
| MANGA-003～006 在追踪矩阵中合并成范围 | 单项需求无法自动核验和独立追责 | 拆分为逐 ID 的聚合、命令、事件与目标证据映射 |
