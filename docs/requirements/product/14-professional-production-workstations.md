# 专业漫剧生产工作台需求

> **需求系列**：OPS / SHOT / CAND / CONT / REV / EDIT / COLLAB  
> **优先级**：P0，作为商业化专业版本进入详细交互和开发的前置基线。  
> **范围原则**：深化核心岗位工作台；已有聚合可承载时扩展原命令与事件，不为页面重复建模。

## 1. OPS 生产控制与排产

### OPS-001：Episode 生产矩阵

**用户故事**：作为制片人，我希望在一个矩阵中查看各 Episode、生产阶段和责任人的计划与实际状态，以便不再跨多个中心拼接进度。

**验收条件**：

- 矩阵按 Episode × 剧本、资产、分镜、图片、视频、音频、审核、剪辑、渲染、发布阶段展示计划量、完成量、阻塞量、负责人和截止时间。
- 完成量来自各领域事实事件投影，用户不得直接编辑派生进度；计划量、负责人和截止时间通过排产命令维护。
- 支持按项目、Episode、阶段、负责人、风险、截止日期和 DEP 新鲜度筛选，并保存个人/共享视图。
- 单元格可下钻到确切对象和工作项，返回时保留矩阵位置；投影不完整时展示水位，不显示虚假 100%。
- 100 个 Episode、每集 500 个生产对象时首屏 P95 ≤ 3 秒，大范围导出转异步任务。

### OPS-002：瓶颈、关键路径与交付预测

**用户故事**：作为制片人，我希望系统解释当前瓶颈和预计交付时间，以便在延期发生前处理。

**验收条件**：

- 风险覆盖缺失依赖、任务排队、Provider 异常、预算、审核 SLA、人员负荷、权利阻断和 DEP 过期链。
- 每条风险显示证据、影响对象、责任岗位、严重度、持续时间和可执行建议。
- 预计完成时间展示计算水位、关键假设和置信区间；数据不足时明确显示无法可靠预测。
- 调整负责人、计划或模型路由前预览成本、时间和审核影响，确认后才执行。
- 风险解除由领域事实重新计算；误报只能带权限和理由确认，不允许无痕清除。

### OPS-003：版本化排产与人工接管

**用户故事**：作为制片人，我希望建立可版本化阶段计划并接管异常任务，以便多人多集并行生产仍有明确责任。

**验收条件**：

- 计划项包含 Episode、阶段、计划起止、目标数量、责任人/岗位、优先级、前置阶段和容量假设。
- 已发布计划不可原地覆盖，调整形成新版本并记录原因与受影响工作项。
- 同一对象不得同时存在互斥执行负责人；转交记录前后负责人、原因和时间。
- 支持暂停未开始计划项、重新排期、批量转交和创建异常 WorkItem，但不得直接篡改业务对象状态。
- 成员移除、权限撤销或持续超期时列出待移交项，完成前不得静默失去责任人。

## 2. SHOT 专业分镜导演工作台

### SHOT-001：可视化构图画布

**用户故事**：作为分镜导演，我希望在画布上直接安排角色、场景、道具、文字和特效，以便所见即所得地完成镜头设计。

**验收条件**：

- 画布展示画幅、安全区、图层、锚点、文字边界、遮罩、视觉动线和景深；选中对象与结构化属性面板双向定位。
- 支持对齐、分布、吸附、锁定、隐藏、组合选择、复制和键盘微调，锁定图层不得被批量移动。
- 安全区、文字重叠、图层引用、资产版本、MotionCue 冲突实时提示，阻断规则与 `MarkShotReady` 一致。
- 保存携带 `expectedVersion`；冲突时保留本地草稿并比较差异，不做最后写入者覆盖。
- 破坏性操作可撤销或二次确认；主流程在 1440×900 桌面分辨率可完成。

### SHOT-002：剧本、前后镜头与时间预览

**用户故事**：作为分镜导演，我希望同时查看剧本上下文、前后镜头和时间效果，以便保持叙事、轴线和动作连续。

**验收条件**：

- Shot 可定位剧本场次、对白行和说话角色；剧本新版本只展示差异，不静默覆盖人工排版。
- 前/当前/后镜头并列展示景别、机位、方向、角色状态、场景时间、采纳候选和连续性告警。
- 时间预览按整数毫秒播放图层可见性、文字、特效、MotionCue、临时音频和口型提示。
- 镜头重排前展示对白引用、审核、剪辑和连续性影响；确认后原子更新，失败不产生部分排序。

## 3. CAND AI 候选与版本管理

### CAND-001：候选比较、评分与采纳

**用户故事**：作为视频导演/美术，我希望同步比较候选和质量证据，以便快速选择合适结果。

**验收条件**：

- 同一生成意图支持 1～4 个候选；比较视图保持同步缩放、播放位置和画幅，支持局部放大与视频同步播放。
- 候选展示模型、Prompt/模板版本、参数、seed、参考媒体、耗时、成本、QC 分数和告警。
- 自动评分展示维度、规则版本和置信度；用户可采纳非最高分候选。
- 采纳只改变当前确切媒体版本引用，不删除其他候选；重新采纳形成新 Shot 版本并触发审核失效和 DEP 评估。
- 媒体不可用、结果未知、输入快照不匹配或权利阻断时禁止采纳。

### CAND-002：派生和候选版本树

**用户故事**：作为创作人员，我希望从满意候选继续派生并保留来源，以便局部迭代且可回溯。

**验收条件**：

- 候选记录 `parentCandidateId`、生成意图、输入快照、AITask 和媒体版本；版本树为事实投影，不能手工伪造关系。
- 支持以候选为参考重新生成、修改 Prompt/参数、替换参考媒体和局部重生成；模型不支持时隐藏对应能力。
- 树中区分成功、失败、取消、已采纳、被替代和被审核版本，并可比较父子 Prompt、参数、输入和质量差异。
- 被采纳、审核、剪辑或追溯引用的候选只能归档，只有无引用临时候选可以删除。

### CAND-003：批量候选处置

**用户故事**：作为视频导演，我希望批量筛选、采纳和返工候选，以便支撑单集数百镜头生产。

**验收条件**：

- 支持按 Episode、模型、任务批次、质量、连续性、权利和人工标签筛选。
- 批量采纳前逐项校验 Shot 版本、候选可用性、权限和审核影响，并展示预计后续任务。
- 执行返回逐项成功、失败、跳过；独立 Shot 的单项失败不隐藏已成功项，支持仅重试失败项。
- 重复提交使用幂等键，不产生重复采纳事件。

## 4. CONT 连续性管理

### CONT-001：Episode 连续性基线

**用户故事**：作为分镜导演/质量负责人，我希望冻结 Episode 连续性基线，以便机器检查和人工判断使用同一依据。

**验收条件**：

- 基线覆盖角色外观/服装/位置、场景空间/时间/天气/光照、道具持有、轴线/视线、StyleAsset、音色和扩展规则。
- 基线引用确切剧本、资产、风格和规则集版本；发布后不可原地修改，新版本触发 DEP 影响评估。
- 规则区分 mandatory/waivable；mandatory 问题普通审核员不得豁免。
- 基线变化不自动修改历史 Shot 或已审核快照。

### CONT-002：跨镜头连续性检查与处置

**用户故事**：作为质量负责人，我希望按场次和镜头序列集中检查连续性，以便处理画面漂移和叙事断裂。

**验收条件**：

- 前/当前/后镜头同步展示，并按角色、场景、道具、方向、风格、音色和严重度聚类问题。
- 问题定位对象版本、Shot、时间点/区域、规则版本和证据，不能只提供泛化文本。
- 状态至少为 `open / acknowledged / fixing / resolved / waived`；resolved 关联修复版本和复检报告。
- 误报/豁免需要权限、理由和范围，规则或目标版本变化后不得自动继承。
- 支持批量创建返工 WorkItem，但不直接修改 Shot、资产或媒体状态。

## 5. REV 专业审片与返工核销

### REV-001：同步审片工作台

**用户故事**：作为审核员，我希望同步查看当前版本、上一版本和制作上下文，以便快速作出有证据的决定。

**验收条件**：

- 图片支持左右、叠加和滑杆对比；视频支持同步播放、逐帧、倍速、循环区间和音频波形。
- 始终显示目标版本、快照哈希、上次结论、QC/连续性问题、制作人和提交时间。
- 决策前校验当前版本仍是 Review 冻结版本；出现新版本时阻止提交并要求重新加载。
- 批量审核只允许相同目标类型、阶段和策略版本，每个对象独立校验并返回部分成功明细。

### REV-002：时码与画面区域批注

**用户故事**：作为审核员，我希望把意见定位到时间、画面区域和质量维度，以便制作者准确返工。

**验收条件**：

- 批注包含文本、严重度、维度、责任阶段、时间点/区间、归一化画面区域和可选附件。
- 批注绑定审核目标版本和快照；新版本只能带入待复核线索，不自动标记解决。
- 批注支持 `open / resolved / reopened`；解决时填写说明并关联修复版本，审核员可复开。
- 请求修改必须至少有一条未解决批注或结构化原因，并按责任阶段创建返工项。

### REV-003：逐条返工核销

**用户故事**：作为审核员，我希望逐条核验修复结果，以便缩短复审时间。

**验收条件**：

- 复审列出上一轮批注、修复说明、前后差异和当前状态。
- 阻断批注未解决前禁止通过；可豁免项需要权限和理由。
- 再次修改形成新轮次并保留历史，不覆盖上一轮批注和决定。
- 审核关闭后批注只读；导出包含版本、批注、责任人、轮次和决定。

## 6. EDIT 专业剪辑工作台

### EDIT-001：多轨时间线核心编辑

**用户故事**：作为剪辑人员，我希望使用可预期的多轨时间线完成轻量成片编辑，以便在平台内闭合交付链路。

**验收条件**：

- 支持视频/图片、对白、BGM、SFX 和字幕轨的添加、移动、裁切、分割、吸附、锁定、静音/独奏、淡入淡出和受控转场。
- 时间单位统一为整数毫秒，帧显示按项目帧率换算；拖拽不得产生负时长、越界或不可解释空隙。
- 波纹、覆盖和插入编辑明确区分，执行前显示受影响 Clip 数量。
- 所有来源引用确切版本；来源失效或 DEP blocked 时阻断，不静默替换。
- 首发定位为轻量剪辑与合成，不承诺复杂调色/合成/DAW；支持导出标准交换包供外部专业工具继续处理。

### EDIT-002：修订、自动保存与冲突恢复

**用户故事**：作为剪辑人员，我希望重要编辑可撤销、可恢复、可比较，以便长时间工作不丢失。

**验收条件**：

- 至少支持 100 步本地撤销/重做；跨保存点通过不可变 EditProject revision 恢复，不改写历史。
- 自动保存间隔不超过 30 秒并在失焦/关闭前触发；失败时保留本地恢复草稿并持续提示。
- 保存携带 `expectedVersion`；冲突提供修订对比、另存修订或放弃，不做最后写入者覆盖。
- 渲染中的 revision 永久冻结，后续编辑创建新 revision。

### EDIT-003：渲染预检与后台任务

**用户故事**：作为剪辑人员，我希望渲染前得到完整预检并可离开页面等待后台完成，以便减少昂贵失败。

**验收条件**：

- 预检覆盖时间线越界/间隙、缺失媒体、响度、字幕安全区、字体权利、画幅、分辨率、帧率、连续性阻断和 DEP 断链。
- 阻断项禁止渲染；警告项需具权限用户填写理由并写审计。
- 渲染展示队列、阶段、进度、预计时间、费用、日志摘要和取消状态，离开页面不影响执行。
- 失败可从安全检查点重试或创建新任务；不覆盖成功制品，结果未知时先对账。

## 7. COLLAB 多人并发协作

### COLLAB-001：在线状态与编辑租约

**用户故事**：作为项目成员，我希望知道谁正在查看或编辑同一对象，以便避免互相覆盖。

**验收条件**：

- 详情页显示查看者、编辑租约持有人、范围和最后心跳；在线状态不作为权限或审计依据。
- Shot、资产和 EditProject 的独占编辑使用有期限租约，断线后自动过期，用户可主动释放。
- owner/admin 强制接管前展示持有人和未保存风险，必须填写原因、通知原持有人并审计。
- 只读查看、评论和审核不无条件占用编辑租约，不同对象可并行编辑。

### COLLAB-002：乐观并发与差异解决

**用户故事**：作为编辑者，我希望冲突时保留双方成果并看到差异，以便避免最后写入者获胜造成丢失。

**验收条件**：

- 写命令携带 `expectedVersion`；冲突统一返回最新版本、冲突对象/字段和重试建议。
- 文本、字段和稳定 ID 集合可比较差异；顺序、时间线或删除冲突不得自动合并。
- 用户可重新应用本地更改、另存草稿/修订或放弃，每种结果记录来源版本。
- 离线草稿恢复前重新校验权限、父对象、版本和权利。

### COLLAB-003：评论、交接与临时代理

**用户故事**：作为团队负责人，我希望讨论、责任和临时代理留在生产对象上，以便人员变化不造成任务失联。

**验收条件**：

- 评论绑定对象确切版本，可 @成员、回复、解决和复开；删除为软删除并保留审计占位。
- 工作项转交记录前后负责人、原因和未完成项；移出项目成员不可继续被指派。
- 代理授权包含授权人、代理人、权限范围、项目和起止时间；不得代理 owner 转移、平台凭据及不可委托权限。
- 代理到期自动失效但保留历史署名；到期仍有未完成工作时通知双方和制片人。

## 8. 统一验收门禁

- 七类工作台各至少具备正常、并发冲突、失败恢复 E2E。
- 页面不得直接编辑派生进度、审核状态、任务结果或 DEP 新鲜度。
- 批量操作先显示范围，执行后返回逐项结果并支持仅重试失败项。
- 长任务必须明确排队、执行、取消中、完成、失败、取消、超时、结果未知，或说明某状态为何不适用。
- 页面级规格必须补齐按钮条件、权限、异常、空状态、键盘、撤销、最低分辨率和可访问性。
