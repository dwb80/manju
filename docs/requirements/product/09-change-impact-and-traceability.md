# DEP 变更影响与全链路追溯需求

> **需求系列**：DEP（Dependency & Evidence Provenance）  
> **优先级**：P0  
> **适用范围**：剧本、角色、场景、道具、风格、分镜表现、生成候选、音频、剪辑、渲染、审核与发布制品。  
> **领域边界**：本能力是跨上下文 CQRS 读模型，不新增业务聚合，也不直接修改其他上下文聚合；升级、重新生成、重新送审仍调用对象所属上下文的命令。

## 1. 目标与术语

平台必须回答两个工业化生产问题：

1. 上游版本改变后，哪些下游成果可能失效，为什么失效，应该从哪里增量返工。
2. 任一候选、审核快照或成片由哪些确切版本、模型、Prompt、参数、人员决策和制品组成。

`依赖边`必须连接确切对象版本或不可变哈希，不允许只记录“当前版本”。`可能过期`是读模型的新鲜度标记，不等于自动作废、自动替换或自动重生成。

## 2. 用户故事与验收条件

### DEP-001：登记生产依赖

**作为** 制片人/领域负责人，**我希望** 系统在发布、冻结、采纳、剪辑、渲染和发布时自动登记输入输出版本关系，**以便** 后续影响分析和追溯不依赖人工填写。

**验收条件**：

- AC-DEP-001-01：创建依赖边时至少记录 `projectId/sourceType/sourceId/sourceVersionOrHash/targetType/targetId/targetVersionOrHash/dependencyType/evidenceEventId/createdAt`。
- AC-DEP-001-02：相同 `evidenceEventId + source + target` 重复投递不得产生重复依赖边。
- AC-DEP-001-03：依赖边只引用不可变版本、快照或制品哈希；缺少版本证据时阻止对象进入“可发布/可采纳/可渲染”状态并给出缺失项。
- AC-DEP-001-04：事件乱序或版本缺口时，该项目投影标记为 `rebuilding`，不得展示“影响范围完整”的误导结论。
- AC-DEP-001-05：支持按源对象反查全部直接和递归下游，并区分直接依赖、派生依赖、审核依赖和发布依赖。

### DEP-002：评估变更影响

**作为** 修改剧本或资产的用户，**我希望** 保存/发布新版本前后看到影响范围，**以便** 判断是否继续、分批升级或保持旧版本。

**验收条件**：

- AC-DEP-002-01：影响评估返回触发变更、旧/新版本、直接与递归受影响对象数量、对象清单、影响原因、严重度和投影水位时间。
- AC-DEP-002-02：预评估不得修改下游状态；版本发布后由事实事件重新计算并记录正式评估结果。
- AC-DEP-002-03：已发布成片、已通过审核快照、正在渲染对象和存在权利风险的对象必须单独分组，并显示不可自动处理原因。
- AC-DEP-002-04：无下游依赖时明确显示“未发现受影响对象”和投影水位，不以空白页代替结论。
- AC-DEP-002-05：投影滞后、重建或事件缺口时显示“结果可能不完整”，禁止一键执行批量升级。

### DEP-003：标记并处置新鲜度

**作为** 分镜导演/视频导演/剪辑人员，**我希望** 下游对象显示其依赖是否仍为当前版本，**以便** 不把旧成果误当作最新成果交付。

**验收条件**：

- AC-DEP-003-01：新鲜度至少包含 `current / potentially_stale / stale / blocked`；该标记作为叠加属性，不替换对象自身生命周期状态。
- AC-DEP-003-02：上游发布新版本后，引用旧版本的下游对象至少标记 `potentially_stale`，并可查看来源、版本差异和影响路径。
- AC-DEP-003-03：用户可“保持锁定旧版本并填写理由”或发起升级计划；确认旧版本不得伪装为 `current`。
- AC-DEP-003-04：权利到期/撤销、源版本不可用或证据缺失时标记 `blocked`，发布预检必须阻断。
- AC-DEP-003-05：新候选被采纳并重新冻结/审核/渲染后，仅沿已更新依赖链恢复 `current`，不得批量清除无关告警。

### DEP-004：制定增量升级与重生成计划

**作为** 制片人，**我希望** 从影响清单生成可预览的增量处理计划，**以便** 控制成本并避免全量返工。

**验收条件**：

- AC-DEP-004-01：计划按对象列出拟执行动作、所属上下文、前置条件、预计任务数、预计成本、审核失效范围和不可自动项。
- AC-DEP-004-02：用户确认前不得创建 AI 任务或改变业务状态；确认后每项调用所属上下文命令并保留 `impactAssessmentId` 关联。
- AC-DEP-004-03：支持仅处理选中项、仅重试失败项、暂停/取消未开始项；已完成项及其成本和证据不得因取消而删除。
- AC-DEP-004-04：计划执行结果区分成功、失败、跳过和人工处理，并可重新评估剩余影响。
- AC-DEP-004-05：无权限、预算不足、模型能力不匹配、审核锁定或权利阻断时不得提交对应动作，并给出可操作原因。

### DEP-005：查询与导出全链路追溯

**作为** 审核员/发布运营/审计人员，**我希望** 从任一成片或候选展开完整证据链，**以便** 复现生成、判断责任并证明权利来源。

**验收条件**：

- AC-DEP-005-01：成片追溯至少覆盖 FinalVideo/PublishRecord → RenderArtifact → EditProject revision → Clip/Audio/Subtitle → 已采纳媒体版本 → AITask execution snapshot → Shot PresentationSnapshot → 剧本/角色/场景/道具/风格确切版本。
- AC-DEP-005-02：AI 执行证据至少包含 provider、model、modelVersion、Prompt 模板版本或文本哈希、参数、seed、参考媒体版本、任务尝试和成本；敏感凭据不得进入追溯结果。
- AC-DEP-005-03：人工证据至少包含采纳人/时间、审核阶段/结论/快照哈希、发布预检与发布记录；按查看者权限脱敏个人和权利材料。
- AC-DEP-005-04：任一节点可向上查看来源、向下查看派生结果；断链节点明确标红并给出缺失证据类型。
- AC-DEP-005-05：支持导出带生成时间、投影水位、项目、根对象、链路摘要和完整性校验哈希的 JSON/PDF 报告；导出操作写入审计。
- AC-DEP-005-06：在常规业务负载下，单项目直接影响查询 P95 ≤ 2 秒；1 万条依赖边内的完整链路查询 P95 ≤ 5 秒，超限时异步生成报告并可查看进度。

## 3. 权限与审计

| 操作 | 最低权限 | 审计要求 |
|---|---|---|
| 查看项目影响清单 | 对源和目标对象均有读取权限 | 记录敏感证据访问 |
| 保持旧版本/填写理由 | 对目标对象有编辑权限 | 记录理由、操作者和版本 |
| 创建升级计划 | 对项目有生产编排权限 | 记录评估、选择范围和成本预估 |
| 执行计划 | 同时满足各目标命令权限 | 逐项保留命令与结果关联 |
| 查看/导出完整追溯 | 审核、发布或审计权限 | 强制记录导出范围、用途和哈希 |

跨项目复制后的资产形成新的项目内版本和 `copiedFrom` 来源证据；后续不存在可变跨项目引用，也不传播源资产更新。

## 4. 页面与旅程

- 资产/剧本/分镜保存或发布：展示影响预评估与正式评估入口。
- 项目工作台：增加“变更影响”视图，支持按来源、类型、新鲜度、负责人和 Episode 筛选。
- Shot、资产、AI 任务、剪辑工程、成片详情：增加“依赖与追溯”页签。
- 批量生成/升级：先展示计划与成本，再由用户确认执行。
- 发布预检：存在 `blocked` 或证据断链时阻断；`potentially_stale` 必须显式确认策略。

## 5. 非目标

- 不自动把所有下游对象切换到最新版本。
- 不允许跨项目共享可变资产引用。
- 不以追溯投影代替源上下文的状态、审计记录或不可变快照。
- 不承诺所有 Provider 能复现完全相同画面；追溯目标是保存输入与执行证据并说明能力限制。
