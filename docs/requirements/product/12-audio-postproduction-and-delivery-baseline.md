# 音频、后期与渠道交付基线

> **状态**：V1 产品基线。本文补充 US-013～US-017 的专业交付要求；具体渠道限制由版本化 DeliveryProfile 承载。

## 1. 音频制品与角色声线

| 制品 | 必要信息 | 主要用途 |
|---|---|---|
| VoiceProfile | 角色、声音来源、授权、语言、音色、语速、音高、年龄感、禁用范围 | 跨集声线一致性 |
| PronunciationLexicon | 词、拼音/音素、重音、适用角色/语言、版本 | 专名和多音字控制 |
| DialogueCue | ScriptLine、角色、文本、情绪、语速、停顿、时间范围 | TTS/录音和字幕同步 |
| MusicCue | 曲目版本、授权、入出点、循环、音量、情绪标签 | BGM 编排 |
| SfxCue | 音效版本、来源、时间点、强度、关联拟声词 | 画面与声音同步 |
| MixSnapshot | 轨道、增益、声像、ducking、插件/规则版本、响度结果 | 可复现混音 |

声音克隆入口默认关闭；只有存在可验证授权、用途、地域和有效期时才能启用。VoiceProfile 变化不得静默重生成已审核对白。

## 2. 配音流程

1. 从已发布 ScriptDocument 生成 DialogueCue，保留来源行和角色。
2. 选择人工录音、普通 TTS 或获授权声音克隆；提交前显示费用、预计时长和授权结论。
3. 支持句级重做、局部文本修正、情绪/语速/停顿调整，不强制重做整集。
4. 发音词典变化时列出受影响对白；用户选择保持旧版本或增量重做。
5. 通过人声质量、发音、静音、削波和授权预检后才能成为可用 AudioAsset。
6. 口型任务必须固定 DialogueCue、AudioAsset 和模型版本；偏差结果写入 QCReport。

## 3. 多轨后期

EditProject 至少支持视频、对白、BGM、SFX、环境声、字幕/文字和效果轨。所有编辑形成 revision；正在渲染的 revision 不被后续编辑覆盖。

V1 必须支持：

- 波形、帧/毫秒时间标尺、吸附、裁剪、分割、移动、淡入淡出和轨道静音/独奏；
- 对白优先的自动 ducking 及人工调整；
- 字幕从剧本/ASR 生成、SRT/VTT 导入导出、硬字幕和软字幕；
- 代理预览、缺失媒体提示、重连媒体和只重渲染受影响区段；
- 撤销/重做、自动保存、revision 对比和渲染前依赖预检；
- 片头、片尾、封面、署名、AIGC 标识和水印模板。

V1 不承诺替代完整专业 NLE；高级调色、复杂合成和第三方插件工程可通过标准中间文件交给外部工具，但往返后必须保留来源和交付版本。

## 4. 母版与交付配置

### 4.1 内部母版

参考母版采用：

- 视频：原项目画幅，恒定帧率 25 或 30 fps，至少 1080 级分辨率；
- 音频：48 kHz，内部母版优先 PCM 24-bit；
- 字幕：UTF-8 WebVTT/SRT 与烧录版可分别生成；
- 文件名包含项目、Episode、画幅、语言、revision 和日期；
- 母版、字幕、封面、权利清单、QC 报告和 manifest 组成标准交付包。

### 4.2 DeliveryProfile

每个渠道配置必须版本化保存：渠道、地域、画幅、安全区、分辨率、帧率、编码器、码率、音频编码/响度、时长、文件大小、字幕、封面、标题/标签限制、AIGC 标识和生效时间。

首个参考网络视频配置为 9:16、1080×1920、H.264、恒定 25/30 fps、AAC 48 kHz，参考响度 `-14 LUFS ± 1 LU`、True Peak ≤ `-1 dBTP`。渠道规则不同时以已验收的渠道配置为准，不得猜测默认值。

## 5. 渲染和发布前检

发布前至少检查：

- 所有媒体存在、可解码、哈希匹配且授权有效；
- 时间线无非预期空洞、黑帧、离线媒体和越界 Cue；
- 音视频总时长、对白/字幕同步和拟声词/SFX 关联有效；
- 分辨率、画幅、帧率、编码、码率、响度、字幕和文件大小符合 DeliveryProfile；
- 当前 FinalVideo 审核版本与当前渲染快照一致；
- 渠道账号凭据有效但不暴露给项目成员；
- AIGC 标识、水印、版权和地域规则满足所选渠道。

预检输出结构化 blocker/warning。blocker 不得绕过；warning 需要有权限人员记录理由。

## 6. 发布、对账与撤回

每个渠道独立创建 PublishRecord。提交超时或结果未知时进入 `reconciling`/等价对账状态，先查询渠道结果再决定重试，避免重复发布。

发布成功必须保存远端内容 ID、URL、规则版本、账号引用、提交/确认时间和回执摘要。渠道不支持远端撤回时生成明确的人工处置项，不伪造成功。

效果回流至少支持播放、完播、平均观看、互动和采集时间；渠道无 API 或无授权时允许人工导入或空值。效果数据不得静默修改历史创作事实。

## 7. 交付包

标准交付包包含：

1. 渠道成片和内部母版；
2. 封面、字幕、音频或平台要求的辅助文件；
3. manifest、schemaVersion、文件哈希和生成时间；
4. QC 报告、审核摘要、权利/授权结论及必要脱敏引用；
5. 制作版本、模型/渲染快照和发布记录索引。

导出必须原子化：失败时不暴露“看似完整”的半成品包；重新导出相同 revision 应得到可解释的一致结果。

## 8. 异常与恢复

| 异常 | 处理结论 |
|---|---|
| TTS 单句失败 | 仅重试失败句；保留成功句及费用 |
| 音频版本变化 | 标记关联字幕、口型和混音可能过期，不静默替换 |
| 源媒体缺失 | 阻止最终渲染，提供重连和来源定位 |
| 渲染失败 | 保留 revision 和日志；允许从安全检查点重试 |
| 渠道规则更新 | 新发布使用新版本；历史 PublishRecord 保留旧规则 |
| 渠道提交结果未知 | 对账优先，不直接重复提交 |
| 发布后权利撤销 | 生成渠道级撤回/人工处置计划并保留证据 |
