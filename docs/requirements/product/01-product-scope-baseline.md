# 产品范围与决策基线

> **版本**：1.0  
> **状态**：已冻结（2026-07-28）。后续变更必须记录决策、影响范围、迁移与验收变化。

## 1. 产品定义

### 1.1 已冻结定位

漫剧 AI 生产平台是面向 AI 内容生产团队的、本地优先、单组织部署的工业化生产管理产品。它统一承接剧本、资产、分镜、AI 生成、审核、后期、成片和发布，不是单一的 AI 绘图工具、视频工具或通用项目管理系统。

### 1.2 已冻结产品形态

首个正式交付形态按“动态漫剧生产”设计：以漫画化角色、场景和画面层为基础，经镜头编排、文字与特效合成、有限动态、配音和剪辑，输出可在视频平台发行的时间轴制品。

以下选择作为首个正式产品基线冻结：

| 决策项 | 冻结选择 | 影响 |
|---|---|---|
| 主制品 | 动态漫剧视频 | Shot、后期时间轴和发布预检均以时间轴制品为主 |
| 画面结构 | 单镜头内支持多画面层；不以印刷页为核心 | `Panel/Page` 暂不成为独立聚合，未来条漫/页漫另行评审 |
| 默认画幅 | 9:16；项目级可选择 16:9 或自定义比例 | 构图安全区、字幕和平台适配必须来自项目表现规格 |
| 部署 | 单实例、单组织、项目级隔离 | Organization/Tenant 不进入当前领域范围 |
| 用户接入 | 管理员创建/邀请 + 企业 SSO；不开放匿名自助注册 | 适配本地优先、单组织的企业生产场景 |
| AI 接入 | 当前通过 Agnes API；适配器扩展必须保持业务层无供应商语义 | 影响模型配置和故障降级 |

### 1.3 产品非目标

- 当前不承诺 SaaS 多租户、订阅计费或跨组织资产市场。
- 当前不承诺 iOS/Android 原生客户端和完整离线编辑。
- 当前不把 AI 小说、企业知识库、直播等远期方向预建为领域上下文。
- 不以内置专业 NLE、绘画软件或三维制作工具的全部能力为目标；需要通过导入、导出和可追溯交接协作。

## 2. 目标用户与核心结果

| 用户 | 需要完成的工作 | 产品必须交付的结果 |
|---|---|---|
| 项目管理员/制片人 | 立项、组队、排期、预算和风险控制 | 可预测的进度、成本与交付状态 |
| 编剧 | 改编、结构化剧本、版本评审 | 可直接进入资产提取和分镜拆解的发布版本 |
| 分镜导演 | 将剧本转为可生产镜头 | 构图、文字、特效、资产和时长均可执行的分镜 |
| 美术设计师 | 建立一致的角色、场景、道具与风格 | 可版本化、可复用、可追溯的资产 |
| 视频导演/AI 操作人员 | 批量生成并筛选候选 | 成本受控、失败可恢复、来源可追溯的镜头结果 |
| 配音/剪辑人员 | 完成音频、字幕、合成和渲染 | 可复现的剪辑工程与成片制品 |
| 审核人员 | 质量、合规、版权和连续性审核 | 明确决策、证据、返工路径和 SLA |
| 发布运营 | 适配渠道、排期、发布和复盘 | 可追踪的发布记录、失败恢复与效果数据 |
| AI/系统管理员 | 管理模型、Prompt、配额、安全和系统配置 | 安全、稳定、可审计的运行环境 |

## 3. 产品完整度标准

正式发布的能力不能只满足“正常路径可点击”，必须同时满足以下八个维度：

1. **业务完整**：正常、异常、撤销、返工、取消和恢复路径均有定义。
2. **权限完整**：每个写命令有角色、项目范围、资源范围和越权验收。
3. **数据完整**：版本、软删除、迁移、导入导出、备份恢复和保留策略明确。
4. **成本完整**：生成前可预估/预占，完成后可结算，失败可释放，超限可阻断或审批。
5. **质量完整**：规则版本、自动质检、人工审核、返工和质量统计闭环。
6. **可靠性完整**：幂等、超时、重试、熔断、死信、补偿和人工接管可验证。
7. **运营完整**：通知、审计、配置、发布记录、监控和指标可查询。
8. **交付完整**：需求、领域、API、Schema、代码、测试和观测证据可追踪。

## 4. 产品成功指标

以下指标必须进入数据字典并可由事件和数据模型计算：

| 指标 | 计算口径 |
|---|---|
| 单集生产周期 | 立项到首次发布成功的自然时长 |
| 单分钟成片 AI 成本 | 已结算 AI 成本 / 发布成片分钟数 |
| 镜头一次通过率 | 首次送审即通过的 Shot 数 / 首次送审 Shot 总数 |
| 平均返工轮次 | 已完成对象的返工次数均值 |
| 生成有效候选率 | 被选中或达到质量阈值的候选 / 全部生成候选 |
| 资产复用率 | 被两个及以上 Shot 引用的已发布资产 / 已发布资产 |
| 发布成功率 | 成功 PublishRecord / 实际执行 PublishRecord |
| 故障恢复时间 | 可恢复故障发生到恢复生产的时长 |

V1 首轮质量目标和商业验证数值分别以[质量与金标准基线](11-quality-and-golden-sample-baseline.md)和[商业、客户与规模基线](13-commercial-customer-and-scale-baseline.md)为准；后续校准必须保留口径、样本和决策记录。

## 5. 产品决策清单

| ID | 决策 | 状态 | 决策结果 |
|---|---|---|---|
| PD-001 | 动态漫剧是否为首个正式主制品 | 已冻结 | 是；首发以动态漫剧视频为主制品，静态页漫不进入当前承诺 |
| PD-002 | 首发画幅及渠道优先级 | 已冻结 | 默认 9:16，支持 16:9/自定义；渠道通过适配器配置，核心域不写死渠道规则 |
| PD-003 | 自助注册、管理员邀请和 SSO 的组合 | 已冻结 | 管理员创建/邀请 + 企业 SSO；不开放匿名自助注册 |
| PD-004 | 是否需要客户可配置多级审核/会签 | 已冻结 | 成片固定初审+复审；镜头/图片/视频默认单级；暂不提供任意会签编排 |
| PD-005 | 项目数据包的交换格式与兼容周期 | 已冻结 | 使用带 manifest/schemaVersion 的版本化项目包；至少兼容当前和前一主版本 |
| PD-006 | 发布效果数据回流的数据源和合规边界 | 已冻结 | 仅在渠道 API、账号授权和合规允许时采集；无权限时保留人工导入/空值，不伪造数据 |
| PD-007 | P0/P1/P2 的发布含义 | 已冻结 | P0=发布阻断，P1=正式发布承诺能力，P2=增强；不得再解释为 MVP |

## 6. 决策变更规则

- 决策变更必须写明提出人、批准人、日期、原因和受影响的 US/聚合/API/Schema/迁移/测试。
- PD-001、PD-003、PD-005 的变更属于架构级变更，必须重新经过 Gate 0～2。
- 渠道清单属于部署配置；新增适配器不改变核心 PublishPlan 状态机，但必须新增平台规则、凭据和回执契约测试。
