# 核心用户旅程

> **用途**：验证产品信息架构、岗位交接、异常恢复和数据闭环。每条旅程必须能够映射到用户故事、页面、领域命令、通知和验收用例。

## 1. 旅程总图

```text
立项与团队
  → 剧本改编与发布
  → 资产提取、制作与发布
  → 漫剧分镜、构图和表现设计
  → AI 图片/视频/音频候选生成
  → 自动质检与人工镜头审核
  → 剪辑、字幕、音效和渲染
  → 成片初审/复审
  → 渠道预检、发布和复盘
  → 资产与模板沉淀
```

任何阶段均可能进入：暂停、取消、失败重试、预算审批、质量返工、版本回退、人员移交和数据恢复。

## 2. J-00 加入组织与首次进入项目

1. 平台管理员创建/邀请用户或配置受信任企业 SSO；系统不开放匿名自助注册。
2. 用户通过密码或 SSO 登录，完成必要的首次改密/安全确认。
3. 用户确认姓名、语言、时区和通知偏好；敏感安全通知不可关闭。
4. 项目 owner/admin 将用户加入项目并分配一个或多个项目角色。
5. 用户首次进入时只看到有权限的项目、工作项和通知；无项目成员关系时显示明确空状态，不泄露其他项目。
6. 系统记录邀请、登录、角色和权限变更审计；异常登录通知用户和平台管理员。

完成标志：用户身份、系统角色、项目角色、会话和通知偏好均有效，能够从自己的待办进入被授权工作。

## 3. J-01 从原创内容到首个可审镜头

| 阶段 | 主责角色 | 用户行为 | 系统反馈/交接 | 完成标志 |
|---|---|---|---|---|
| 立项 | 制片人 | 创建 planning 项目，确认画幅、预算、排期和团队后启动 | 校验配置并通知成员 | Project active、默认 Episode 可用 |
| 剧本 | 编剧 | 导入/创作、AI 分析、修改并发布版本 | 提取角色/场景/道具候选 | Script published |
| 资产 | 美术 | 合并重复候选、制作一致性包、标记 ready 并发布 | 版本可被 Shot 引用 | 关键资产 published |
| 分镜 | 分镜导演 | AI 拆镜、逐条采纳、构图、气泡、拟声词、特效和时长 | 实时显示缺失依赖和安全区问题 | Shot ready |
| 生成 | 视频导演 | 选择模型/策略、查看成本预估并生成候选 | 进度、失败原因、候选对比 | 已选候选可送审 |
| 质检/审核 | 系统+审核员 | 自动检查后人工通过或返工 | 通知责任人并建立 WorkItem | Shot approved 或明确返工项 |

关键异常：剧本版本过期、资产未发布、预算不足、Provider 超时、候选全部不合格、审核 SLA 超时。

## 4. J-02 从既有 IP/剧本导入项目

1. 制片人创建空项目并选择“导入已有内容”。
2. 编剧批量上传受支持格式，预览章节、角色、对白和格式告警。
3. 系统只生成导入计划，不直接污染正式数据。
4. 用户处理重名、重复资产、缺失字体和格式冲突。
5. 确认后在一个导入批次内写入；失败时回滚或明确列出部分成功项。
6. 生成导入报告、来源哈希和审计记录。
7. 后续修改保留原始文件和映射关系。

完成标志：导入内容可追溯、可回滚、可继续走正式发布与分镜流程。

## 5. J-03 跨集资产一致性维护

1. 美术查看项目一致性看板和高频复用资产。
2. 创建角色/场景/道具新版本，而非覆盖已用版本。
3. 系统列出引用旧版本的 Shot 和已冻结快照。
4. 美术选择仅用于新镜头，或发起受影响镜头升级批次。
5. 分镜导演逐项确认构图和 Prompt 差异。
6. 已批准镜头升级后审核失效，自动进入返工/复审。

完成标志：所有版本引用明确，没有静默替换和不可解释的画面漂移。

## 6. J-04 批量生成与故障恢复

1. 视频导演选择 Shot 批次、候选数和模型策略。
2. 系统展示预计成本、预算余量、并发和预计完成时间。
3. 用户确认后原子预占预算并创建独立幂等任务。
4. 任务执行中实时展示队列、进度、Provider 和重试次数。
5. 失败按策略自动重试；不可重试或耗尽后生成可操作错误和 WorkItem。
6. 用户可仅重试失败项、切换兼容模型、降低规格或申请追加预算。
7. 取消任务释放未消费预占，不删除已完成候选。

完成标志：每个任务费用已结算/释放，结果和失败均可追溯，无永久“执行中”任务。

## 7. J-05 审核、返工与责任交接

1. 送审方提交不可变快照并选择适用审核策略。
2. 系统自动质检；阻断问题必须先修复，警告允许带理由继续。
3. 审核队列按项目、SLA、优先级和技能分派。
4. 审核员查看完整上下文，执行通过、请求修改或驳回。
5. 请求修改必须定位对象、维度、时间点和责任角色。
6. 系统创建 WorkItem 并通过站内通知；达到阈值后邮件/升级。
7. 修复后提交新快照，保留前后差异与审核链。

完成标志：审核结论绑定确切版本，返工责任和 SLA 明确，不能以聊天消息替代正式决策。

## 8. J-06 成片发布与复盘

1. 剪辑人员冻结 EditProject revision 并发起最终渲染。
2. 系统完成字幕、音频、字体、版权、规格和可访问性预检。
3. 成片依次完成初审和复审；新渲染使旧结论失效。
4. 发布运营选择账号、渠道、时间、范围、标题、标签和封面。
5. 每个渠道独立创建 PublishRecord，单渠道失败不覆盖其他成功记录。
6. 可重试错误自动/人工重试；凭据或合规错误阻断并通知负责人。
7. 成功后回写平台链接和回执；后续采集效果数据并进入复盘。
8. 项目沉淀高表现 Prompt、构图模板、资产和失败案例。

完成标志：制品、审核、渠道配置、回执和效果数据形成闭环。

## 9. J-07 误删、版本错误与灾难恢复

1. 用户删除前看到影响范围和保留期；关键对象要求二次确认。
2. 软删除对象进入统一回收站，不允许继续被新对象引用。
3. 恢复前重新校验父对象、名称、版本和引用冲突。
4. 永久删除仅限授权角色，记录原因和不可恢复提示。
5. 系统备份按计划执行并校验；恢复演练记录 RPO/RTO。
6. 故障恢复后执行引用、事件位点、文件和数据库一致性检查。

完成标志：误操作可恢复，永久删除可审计，灾难恢复结果可验证。

## 10. J-08 上游变更、增量返工与成片追溯

1. 编剧或美术在发布剧本/资产新版本前查看影响预评估，确认受影响的 Shot、候选、审核、剪辑和成片范围。
2. 新版本发布后，系统基于领域事实事件更新依赖投影；引用旧版本的下游对象显示新鲜度和影响路径，但不被静默替换。
3. 制片人选择保持锁定旧版本，或创建仅包含选中对象的增量升级计划。
4. 系统展示预计任务数、成本、审核失效范围、权限/权利阻断和人工处理项；用户确认后才调用各上下文命令。
5. 执行中可取消未开始项、仅重试失败项；已完成候选、费用、快照和审计证据保留。
6. 分镜、审核和后期分别完成新候选采纳、快照冻结和重新渲染，对应依赖链恢复为当前。
7. 发布运营从成片打开追溯视图，验证渲染、剪辑、媒体候选、AI 执行快照、分镜快照、资产/剧本版本、权利材料和人工审核链。
8. 存在断链或权利阻断时发布预检失败；有权限的人员可导出带完整性哈希和投影水位的追溯报告。

完成标志：变更影响可解释、返工范围可控、任何交付制品均能追溯到确切输入和决策证据。

映射需求：[DEP-001～DEP-005](09-change-impact-and-traceability.md)。

## 11. J-09 多集并行排产与专业岗位协作

1. 制片人在生产控制塔发布 Episode 阶段计划，设置目标、负责人、容量假设和截止时间。
2. 系统以领域事实更新生产矩阵，识别依赖、队列、预算、审核、权利和人员瓶颈，并展示预测水位与假设。
3. 分镜导演在可视化画布完成构图，通过剧本定位、前后镜头和时间预览检查叙事与方向连续性。
4. 视频导演在候选比较台查看同步画面、质量维度、参数与成本，从版本树采纳确切媒体版本。
5. 连续性负责人按场次聚类问题并创建返工项，修复后关联新版本和复检证据。
6. 审核员逐帧/区域批注；制作者逐条填写修复说明，复审核销阻断项。
7. 剪辑人员在多轨时间线完成轻量合成，通过修订、自动保存和冲突恢复保护工作，预检后后台渲染。
8. 多人同时工作时展示编辑租约；冲突保留本地草稿并比较差异，人员转交和代理留有审计。
9. 制片人在控制塔确认瓶颈解除和预计交付时间，异常项可批量转交或人工接管。

完成标志：团队可并行推进多集生产，核心岗位无需依靠外部表格拼接状态，交接、冲突和返工均可追溯。

映射需求：[专业漫剧生产工作台需求](14-professional-production-workstations.md)。

## 12. 旅程验收门禁

- 每条旅程至少有一条正常 E2E 和一条异常/恢复 E2E。
- 每次岗位交接都有状态、责任人、通知和 SLA，而不是仅改变页面。
- 每个异步步骤都能取消、超时、重试或人工接管。
- 每个关键成果都绑定版本和来源。
- 用户无需跨多个中心手工拼接同一生产任务的状态。
