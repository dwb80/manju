# 漫剧质量标准与金标准样本基线

> **状态**：V1 产品基线。数值是首轮产品验收线，不等同于对外 SLA；上线后可通过有版本的 QualityRuleSet 校准，不得追溯改变历史结论。

## 1. 质量判定模型

质量问题统一分为四级：

| 级别 | 定义 | 处理结论 |
|---|---|---|
| blocker | 无法发行、权利/安全不成立、制品损坏或核心剧情错误 | 必须修复，不可豁免发布 |
| major | 明显影响观看、角色识别、连续性、同步或专业感 | 必须修复；紧急覆盖需双人审批和审计 |
| minor | 不影响理解但影响完成度 | 可返工或由授权审核人带理由接受 |
| suggestion | 优化建议 | 不阻断，进入复盘数据 |

自动规则只产生“检测结论”；最终业务结论由规则配置指定。任何人工豁免都必须记录操作者、原因、范围、有效版本和到期条件。

## 2. 分阶段质量标准

### 2.1 内容与剧本

- 人物动机、关键因果、上下集承接和结尾钩子不存在 blocker。
- 发布剧本中的角色、场景、道具和对白可映射到结构化对象；无法解析项必须明确标记人工处理。
- 错字、漏字、角色名混用和对白归属错误为可定位问题；发布前 blocker/major 为 0。
- Episode 预计时长与 Shot 时长总和偏差不超过 10%，超出时必须人工确认。

### 2.2 画面与连续性

- 核心角色身份、五官锚点、体型和标志特征不得出现不可解释漂移。
- 服装、伤痕、道具持有、昼夜、天气、人物左右方向和空间轴线必须符合 Bible/连续性状态。
- 手部、肢体、面部、穿模、重复主体和文字乱码等结构错误按可见程度分级。
- 角色脸部或关键主体不得落入渠道 UI 高风险遮挡区；文字不得越出文字安全区。
- blocker/major 连续性问题在送审版本中必须为 0；人工评分“角色一致性”和“场景连续性”均不得低于 4/5。

### 2.3 动态与镜头

- 不允许无意图闪烁、主体突变、背景沸腾、运动方向反转或明显的帧间身份漂移。
- MotionCue 的时间、目标图层、起止值和冲突优先级必须可解释。
- 光敏风险规则命中 blocker 时禁止渲染为可发布成片。
- 预览和最终渲染的构图、时间点和动作顺序一致；允许分辨率/码率不同。

### 2.4 文字与字幕

- 剧情对白与气泡说话人、字幕文本和音频台词一致。
- 不允许文字越界、关键主体遮挡、气泡尾指向错误或同屏文字不可判读。
- 字幕与语音起止偏差目标不超过 100ms，超过 200ms 为 major；特殊表演可人工确认。
- 字体、字形、语言和授权证据必须随快照冻结。

### 2.5 音频

- 人声无削波、爆音、明显底噪、非预期静音或不可理解发音。
- 角色声线、语速和关键发音跨集保持一致；专有名词采用项目发音词典。
- 参考网络交付响度为 `-14 LUFS ± 1 LU`，True Peak 不高于 `-1 dBTP`；渠道配置有更严格规则时以渠道为准。
- 对白为主的片段中，BGM/SFX 不得持续掩蔽对白；自动 ducking 结果必须可人工调整。

### 2.6 技术与交付

- 无损坏文件、缺帧、意外黑帧、音视频轨缺失、时长不一致和不可解码问题。
- 画幅、分辨率、帧率、编码、码率、字幕和元数据符合所选 DeliveryProfile。
- 最终文件哈希、渲染输入快照哈希和发布记录可关联。
- 权利、安全、审核或渠道预检 blocker 必须为 0。

## 3. 首轮产品质量目标

| 指标 | V1 验收目标 | 统计口径 |
|---|---:|---|
| 镜头首次送审通过率 | ≥ 60% | 首次即 approved 的 Shot / 首次送审 Shot |
| 生成有效候选率 | ≥ 25% | 被采纳或达到质量线的候选 / 全部候选 |
| 字幕/文字越界送审前拦截率 | ≥ 95% | 送审前发现的问题 / 金标准已知问题 |
| blocker 自动规则召回率 | ≥ 95% | 命中 blocker / 金标准 blocker |
| 自动 QC 误报率 | ≤ 15% | 被人工判为非问题的自动问题 / 自动问题 |
| 发布技术预检成功率 | ≥ 99% | 一次通过技术预检的标准交付包 / 标准交付包 |
| 可恢复任务永久卡在处理中 | 0 | 超过超时与接管窗口仍无结论的任务 |
| 成片证据链完整率 | 100% | 可追溯到输入、模型、人工审核和权利的成片 / 成片 |

指标未达到不必自动阻断全部上线，但必须有根因、改进负责人和产品负责人签署的风险接受；blocker 为 0 和证据链完整率 100% 不可降低。

## 4. 金标准样本项目

V1 建立一个版本化 `GoldenProject`，不得只使用开发者临时数据。最低覆盖：

- 3 个 Episode，每集 60～120 秒，总计不少于 60 个 Shot；
- 3 个核心角色、2 套服装变化、5 个场景、5 个关键道具；
- 双人对话、多人同框、动作、反应镜头、回忆、昼夜变化和跨集连续性；
- 气泡、旁白、拟声词、漫画特效、有限动态、TTS、BGM、SFX 和字幕；
- 至少 1 次上游剧本变更、1 次资产授权到期、1 次 Provider 超时和1次部分批量失败；
- 至少 2 个渠道交付配置，其中一个采用 9:16。

金标准仓必须保存：输入素材及授权替身、期望结构、已知问题清单、期望 QC 结果、人工评分、模型/规则版本、成本基线、成片和交付包哈希。

## 5. 评测与回归

1. 模型、Prompt 编译器、QualityRuleSet、渲染器或渠道规则发生主版本变化时，必须重跑受影响样本。
2. 自动评测输出不得覆盖人工金标准；差异进入待判定队列。
3. 回归必须同时比较质量、成本和时长，禁止只用生成成功率判定升级。
4. 金标准变更需由编剧/导演、美术、后期、审核至少三类岗位共同签署，并保留旧版本。
5. 规则性能按题材、角色肤色/年龄、画幅、语言和模型分层统计，避免总平均掩盖局部失效。

## 6. 审核表

最终审核至少包含剧情连贯性、角色一致性、画面质量、动态质量、文字字幕、声音、技术规格、内容安全和权利九个维度。每个维度记录 1～5 分及 blocker/major/minor 数量；任何 blocker 或未关闭 major 均不得发布。
