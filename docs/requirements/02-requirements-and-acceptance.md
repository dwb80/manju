## 一、需求规格概述

### 1.1 项目名称

**漫剧 AI 生产平台** —— AI 漫剧工业化生产平台。

### 1.2 一句话定位

面向 AI 内容生产团队的企业级生产管理平台，对标"ChatGPT + Midjourney + Runway"的多模态创作场景，并整合"剧本 → 分镜 → 资产 → AI 生成 → 审核 → 发布"的生产流水线。

### 1.3 项目目标

1. 提供基于 Agnes AI 官方 API 的统一 AI 创作入口。
2. 支持多模态（文本/图片/视频）输入输出与多轮上下文交互。
3. 提供完整的会话管理、历史回溯、收藏能力。
4. 打造可本地运行的 AI 创作工具。
5. 支持从剧本创作到分镜、图片、视频、审核、发布的完整生产流程。

### 1.4 项目范围

**范围内（In Scope）**：
- Web 端（PC 优先，响应式适配移动端）
- V1 为本地优先、单组织部署；权限隔离到项目级
- 会话系统、内容生成
- 三大核心能力：对话会话（Agnes 2.0 Flash）、图片生成（Agnes Image 2.1 Flash）、视频生成（Agnes Video V2.0）
- 项目管理、剧本、动态漫剧表现分镜、角色/场景/道具/音频资产、审核质检、后期渲染、发布
- 用户与认证、命令级权限、通知、配置、审计、统一回收站、版本化导入导出、备份恢复和受控数据迁移

**范围外（Out of Scope）**：
- 移动原生 App（iOS/Android）
- 第三方开放平台 API 接入（V3 阶段考虑）
- 离线模型部署
- SaaS 多租户、订阅计费和跨组织资产共享

### 1.5 术语约定

- **MUST**：强制需求，缺失则产品不可用。
- **SHOULD**：建议需求，强烈推荐实现。
- **MAY**：可选需求，根据资源情况决定。

> **领域术语**：本文档与 [DDD 统一语言术语表](../domain/03-glossary.md) 保持一致。代码、API、UI 涉及业务对象时，统一使用 DDD 术语（如"分镜 / 分镜板"而非"镜头 / 分镜列表"，如"角色 / 场景 / 道具"而非"角色 / 场景 / 物品"）。

### 1.6 验收等级定义

- **P0（正式发布阻断）**：首个正式版本必须完整验收，缺失会破坏核心价值、数据、权限、成本、质量或恢复能力。
- **P1（正式产品承诺）**：可按版本分批交付；一旦进入版本范围，必须满足完整验收，不得以主路径可用代替。
- **P2（增强功能）**：锦上添花的增强功能。

完整定义与评分公式见 [产品设计规格总纲 §附录二 功能优先级分级体系](01-product-design-spec.md)。

### 1.7 验收条件（AC）编写原则

- **可测试性**：每个 AC 都有明确的验证方法（点击、断言、数据查询）。
- **完整性**：覆盖正常流程 + 异常流程 + 边界情况。
- **独立性**：每个 AC 独立可验证，不依赖其他 AC 状态。
- **明确性**：避免"友好"、"合理"、"明显"等模糊词汇，使用具体数值和条件。

## 二、功能需求（含验收条件）

### 2.1 项目立项阶段

#### US-001: 创建新项目

**用户故事**：作为制片人，我想要创建一个新项目，以便组织一个漫剧的剧本、剧集、资产和团队。

**领域归属**：[§3.1 项目管控](../domain/contexts/01-project-management.md) - 聚合根 `Project`。

**验收条件**：
- [ ] **AC1.1 必填校验**：未填写项目名称、结构类型、描述或默认画幅时提交按钮置灰并提示"请填写必填项"；项目名称为空或长度超过 100 字符时报错"项目名称 1-100 字符"。
- [ ] **AC1.2 命名唯一性**：同所有者下项目名称重复时返回 `CONFLICT_ERROR` 并提示"项目名称已存在"。
- [ ] **AC1.3 默认初始化**：创建成功后自动创建第 1 集（`Episode`）并进入项目工作台，项目和 Episode 初始状态均为 `planning`；完成画幅、预算和必要团队配置后可执行 `StartProject` 进入 `active`。
- [ ] **AC1.4 所有者授权**：服务端从当前认证主体派生 `ownerId`，创建者自动成为 `owner` 角色（依据 [§1.3 ProjectRole](../domain/contexts/01-project-management.md)）；普通客户端不得通过提交任意 `owner` 冒充其他所有者。
- [ ] **AC1.5 资产库自动创建**：项目创建后自动生成空资产库（角色/场景/道具/参考图四个分类），数量为 0。
- [ ] **AC1.6 ID 生成**：项目 ID 由系统生成，格式为 `proj_` + 12 位 base36 随机串（与数据库 `id TEXT 主键` 约定一致）。
- [ ] **AC1.7 软删除恢复**：项目列表支持软删除过滤（`deleted_at IS NULL`），软删除后 30 天内可恢复，超过 30 天走物理删除（管理接口）。
- [ ] **AC1.8 响应时间**：创建接口 P95 ≤ 1s，包含事务和事件发布。
- [ ] **AC1.9 并发幂等**：同一用户 1 秒内重复点击创建按钮只产生 1 条项目记录（前端防抖 + 后端幂等键）。
- [ ] **AC1.10 国际化**：项目名称、描述支持中英文混排，存储为 UTF-8。
- [ ] **AC1.11 存储模式**：`managed` 由平台在获准工作区内生成和管理目录；`existing` 绑定管理员已授权的现有目录，必须做规范化、允许根校验、可读写预检和冲突预览，不得接受任意客户端绝对路径。平台不得在项目删除时默认删除 `existing` 原始目录。
- [ ] **AC1.12 项目状态**：统一机器值为 `planning / active / paused / completed / archived`，UI 分别显示“策划中 / 制作中 / 已暂停 / 已完成 / 已归档”；创建接口不接受客户端自定义初始状态，旧中文状态值仅允许在迁移适配层读取。
- [ ] **AC1.13 计划集数**：`plannedEpisodeCount` 是计划值，不是实际 Episode 数量；实际数量由 Episode 集合计算。两者不一致时显示计划/实际，不得互相静默覆盖。
- [ ] **AC1.14 当前实现兼容**：现有 `ProjectFormDraft` 的 `category/status/episode_count/owner/due_date/storage_path` 和 `/api/projects/existing` 属兼容输入；适配层按字段映射转换到规范命令。兼容字段存在不代表客户端获得所有者或状态写权限。

**字段规范**：见 [§3.1 项目创建表单](#31-项目创建表单)。

**依赖**：无（首条用户故事）。

**优先级**：P0

**API 契约**：见 [§5.1.1 `POST /api/v1/projects`](#511-post-apiprojects)。

#### US-002: 创建剧集

**用户故事**：作为制片人，我想要在项目下创建多个剧集，以便管理系列化项目的多集内容。

**领域归属**：[§3.1 项目管控](../domain/contexts/01-project-management.md) - 实体 `Episode`（聚合内）。

**验收条件**：
- [ ] **AC2.1 字段校验**：剧集标题 1-100 字符，剧集序号 1-999 整数；同项目内 `episodeNumber` 不可重复。
- [ ] **AC2.2 默认状态**：剧集状态初始化为 `planning`；项目归档时剧集进入 `archived`，恢复项目不自动恢复剧集。详细制作阶段由剧本、分镜、生成、审核和发布事实派生，不允许多个页面任意写中文阶段字符串。
- [ ] **AC2.3 子资源创建**：剧集创建事务内生成空剧本（`Script`）和空分镜板（`Storyboard`）；角色/场景/道具资产库属于项目级事实，不为每集复制一套事实源。
- [ ] **AC2.4 角色权限**：仅 `owner` / `admin` 角色可创建剧集（依据 [§1.3 ProjectRole](../domain/contexts/01-project-management.md)）。
- [ ] **AC2.5 序号自动递增**：不指定 `episodeNumber` 时自动取当前最大值 +1。
- [ ] **AC2.6 删除前置条件**：剧集删除前必须无关联分镜板和成片（依据 [§1.6 不变量](../domain/contexts/01-project-management.md)），否则返回 `CONFLICT_ERROR` 列出冲突资源。
- [ ] **AC2.7 归档级联**：项目归档时所有剧集自动归档，恢复时不会自动恢复（需手动操作）。
- [ ] **AC2.8 管理入口**：V1 可在 `/projects/workbench` 的“项目剧集”页签内管理，无需为了 P0 单独建设页面；入口必须保留 projectId 和当前页签上下文，并可从剧本、分镜和发布对象返回所属 Episode。独立深链页面属于体验增强，不改变领域归属。
- [ ] **AC2.9 单一事实源**：业务 Episode 唯一归属 `Project`，规范写接口为 `/api/v1/projects/{projectId}/episodes`。现存 `/api/script-episodes` 记录仅表示某个 ScriptDocument 的结构化剧集/章节投影，必须关联规范 `projectEpisodeId`，不得拥有独立于 Project Episode 的编号、归档、发布或删除生命周期。
- [ ] **AC2.10 双模型迁移**：在 `project_episodes` 与 `script_episodes` 完成 Inventory、映射、冲突处理和 Cutover 前，两者并存属于实现缺口而非“两种产品模式”；禁止新增无 `projectEpisodeId` 的孤儿 ScriptEpisode。迁移后 `/api/script-episodes` 只保留兼容读取或文档结构编辑能力。
- [ ] **AC2.11 删除预检**：删除按钮调用只读预检，列出 Script、Storyboard、Shot、音频、剪辑和 FinalVideo blocker；当前前端未调用预检属于 P0 实现差距，不得通过降低需求关闭。

**字段规范**：见 [§3.2 剧集创建表单](#32-剧集创建表单)。

**依赖**：US-001。

**优先级**：P0

**API 契约**：见 [§5.1.2 `POST /api/v1/projects/{projectId}/episodes`](#512-post-apiprojectsidepisodes)。

### 2.2 剧本生产阶段

#### US-003: 剧本文档与导入管理

**用户故事**：作为编剧，我想要管理剧本的多个版本，以便追溯修改、对比差异并安全回退。

**领域归属**：[§3.2 剧本创作](../domain/contexts/02-script-creation.md) - 聚合根 `Script`。

**验收条件**：
- [ ] **AC3.1 零基创建**：选择"新建空白剧本"时进入编辑器，初始状态 `draft`。
- [ ] **AC3.2 版本复制**：从已有版本创建新版本时自动复制内容（富文本 + 批注），版本号 +1（如 v1.0 → v2.0），新版本引用 `previousVersionId` 形成版本链。
- [ ] **AC3.3 版本对比**：支持选两个版本并排对比，差异按行高亮（新增绿色 / 删除红色 / 修改黄色）。
- [ ] **AC3.4 版本回退**：从 v2.0 回退到 v1.0 通过"基于 v1.0 创建新版本"实现，不修改 v1.0 的不可变快照。
- [ ] **AC3.5 编辑锁**：单人进入编辑时进入锁定，30 分钟无活动自动释放；其他用户以只读模式打开（看到锁图标和剩余时间）。
- [ ] **AC3.6 锁冲突提示**：被锁定的剧本对其他用户显示"用户 X 正在编辑，剩余 28 分钟"，并提供"只读预览"入口。
- [ ] **AC3.7 强制释放**：admin 可强制释放锁，记录到审计日志（含操作人、原因、时间）。
- [ ] **AC3.8 多人查看**：锁定期间其他用户可查看内容（只读），但不能保存。
- [ ] **AC3.9 发布快照**：执行"发布"时创建不可变 `ScriptDocument` 快照，已分镜引用的旧版本不变（依据 [§1.3 不变量](../domain/contexts/02-script-creation.md)）。
- [ ] **AC3.10 编辑器**：支持富文本（加粗、斜体、标题、列表、引用）、场景标题层级（场 1 / 场 2）、对白格式化。
- [ ] **AC3.11 导入格式**：支持 Markdown（`.md`）、Final Draft（`.fdx`）、纯文本（`.txt`）和结构化 JSON（`.json`）；不支持的格式在写入前明确拒绝。
- [ ] **AC3.12 导入方式**：支持本地文件、URL 和粘贴文本；URL 导入必须经过协议、大小、超时和内容安全校验。
- [ ] **AC3.13 解析预览**：确认导入前展示章节、场景、角色、对白、道具、格式告警和资产匹配结果，用户可取消且不产生业务数据。
- [ ] **AC3.14 导入边界**：单文件不超过 50MB；单批最多 10 个文件；支持选择部分章节导入。
- [ ] **AC3.15 原子写入**：单文件确认后以导入批次原子写入剧本文档、来源、版本和报告；失败不得暴露半成品。
- [ ] **AC3.16 批量结果**：批量导入逐文件返回成功、失败和原因；失败文件不回滚已独立确认成功的文件。
- [ ] **AC3.17 资产候选**：解析出的角色、场景和道具只能作为待确认候选，不得默认发布或静默覆盖同名资产。
- [ ] **AC3.18 可追溯性**：保存源文件摘要、格式/版本、操作者、导入时间、解析器版本、映射决策和导入报告。

**字段规范**：见 [§3.3 剧本编辑器字段](#33-剧本编辑器字段)。

**依赖**：US-002。

**优先级**：P0

#### US-004: AI 辅助剧本分析

**用户故事**：作为编剧，我想要 AI 自动识别剧本中的角色、场景和道具，以便快速建立资产草稿。

**领域归属**：[§3.2 剧本创作](../domain/contexts/02-script-creation.md) - `Script.analysis` 值对象 + 事件 `ScriptAnalyzed` 触发资产库。

**验收条件**：
- [ ] **AC4.1 触发条件**：仅 `draft` / `analyzed` 状态可触发分析，`analyzing` / `published` 不可触发。

#### US-033: AI 辅助剧本创作

**用户故事**：作为编剧，我想要 AI 辅助生成、优化、改写剧本内容以及拆场景/拆分镜，以便提升创作效率且保留完全的采纳控制权。

**领域归属**：[§3.2 剧本创作](../domain/contexts/02-script-creation.md) - 聚合根 `ScriptCreationTask` + 值对象 `CreationCandidate`。AI 执行通过事件委托 AI 任务调度上下文。

**验收条件**：

- [ ] **AC33.1 使用入口和适用角色**：入口位于剧本编辑器工具栏和右键菜单；适用角色为编剧（`script_writer`）和项目负责人（`project_owner`）。`generate` 类型仅限 `draft` 状态空白剧本或通过指令扩展已有内容。
- [ ] **AC33.2 任务类型**：支持六种创作类型——`generate`（AI 剧本生成）、`optimize`（AI 剧本优化/改写）、`scene_generate`（AI 场景生成）、`dialogue_generate`（AI 对话生成）、`split_scenes`（AI 剧本拆场景）、`split_shots`（自动拆 Shot）。每种类型有明确的输入范围和剧本状态约束（依据 [§4.0 任务类型枚举](../domain/contexts/02-script-creation.md)）。
- [ ] **AC33.3 输入范围**：支持四种输入范围——`full`（全文）、`selection`（选区文本）、`scene`（单个场景）、`dialogue`（单段对白）。选区模式通过 `TextRange { offset, length }` 精确定位。
- [ ] **AC33.4 结果为候选**：AI 生成结果始终为**候选**（`CreationCandidate`），不直接覆盖原文。候选包含 `content`（生成内容）、`diff`（与原文差异）、`confidenceScore`（置信度）和最多 3 个 `alternativeResults`（备选）。
- [ ] **AC33.5 预览与采纳机制**：用户可在候选预览面板左右对比原文与候选内容，差异行高亮显示。采纳（`AdoptCreationCandidate`）后候选内容应用回剧本；拒绝（`RejectCreationCandidate`）后任务终结。采纳后不可撤销到候选状态，但可通过剧本版本回退恢复原文。
- [ ] **AC33.6 Stale 处理**：任务完成时对比发起时的 `sourceScriptVersion` 与当前剧本版本，不一致则标记 `stale = true`。采纳 stale 候选需用户二次确认（"剧本已修改，确认仍要采纳？"）。`inputSnapshot` 在创建时冻结，保证 AI 调用输入可追溯。
- [ ] **AC33.7 Prompt/模型/费用/来源记录**：每次创作任务记录 `PromptSnapshot`（模板 ID + 版本 + 渲染结果 + 参数）和 `ModelExecutionSnapshot`（模型 / Token / 耗时 / 成本 / requestId），可在创作历史中查看和导出。
- [ ] **AC33.8 异步任务**：创作任务为异步执行。创建后返回 `202 Accepted` + `taskId`，前端通过 `GET /api/scripts/{id}/creation-tasks/{taskId}` 轮询或 SSE 获取进度。单次超时 120s。
- [ ] **AC33.9 超时与取消**：`pending` / `generating` 状态可取消（`CancelCreationTask`）；已 `completed` 的任务不可取消。超时后标记 `failed`，支持重试。
- [ ] **AC33.10 重试机制**：失败任务支持一键重试（`RetryCreationTask`），最多 3 次，指数退避（10s / 30s / 60s）。超过 3 次后进入 `failed` 终态。
- [ ] **AC33.11 过期策略**：`completed` 状态任务超过 24h 未处理自动转为 `expired`，由定时任务触发。
- [ ] **AC33.12 并发控制**：同一 `scriptId + taskType + inputScope` 的 `pending` / `generating` 状态任务不可重复创建，返回 `command_already_processed` 错误。
- [ ] **AC33.13 内容安全**：生成内容经过敏感词过滤和内容安全检查；命中敏感词时返回 `content_safety_violation` 错误，不产出候选。输入内容同样经过安全校验。
- [ ] **AC33.14 权限校验**：创建任务需 `script.write` 权限；采纳候选需 `script.write` 权限；查看任务列表和候选需 `script.read` 权限。项目归档后拒绝所有写操作。
- [ ] **AC33.15 split_shots 特殊流转**：`split_shots` 类型候选被采纳后，产出 `ShotSuggestionsGenerated` 事件，由分镜导演上下文消费创建 Shot 草稿（待人工确认），不直接创建分镜。
- [ ] **AC33.16 采纳后状态联动**：若剧本处于 `analyzed` 状态，采纳候选更新内容后自动回退到 `draft`，原分析结果标记 `stale`（与 `UpdateScript` 行为一致）。
- [ ] **AC33.17 幂等性**：`AdoptCreationCandidate` 幂等——已 adopted 的任务重复采纳返回原结果引用，不重复修改剧本。

**依赖**：US-003、US-004（`split_shots` 依赖分析结果）。

**优先级**：P1

**API 契约**：见 [§5.1.28 `POST /api/scripts/{id}/creation-tasks`](#5118-post-apiscriptsidcreation-tasks)。

- [ ] **AC31.4 冲突预览**：写入前展示重名、缺失依赖、授权限制和预计存储/生成成本，用户逐项选择重命名、跳过或取消。
- [ ] **AC31.5 版本与血缘**：目标资产创建新ID和version 1，记录sourceProjectId、sourceAssetId、sourceVersion和复制批次；后续不自动同步。
- [ ] **AC31.6 原子与报告**：复制批次逐项报告成功/失败；单资产及其必需依赖原子写入，不暴露半成品。
- [ ] **AC31.7 影响隔离**：来源资产后续修改、归档或删除不得静默改变目标副本；授权撤销时产生影响通知和发布阻断检查。
- [ ] **AC31.8 审计与成本**：记录操作者、目的、来源、目标、版本、授权决策和复制成本；后续生成费用归目标项目。

**依赖**：US-007、US-008、US-030。

**优先级**：P1；同系列多项目生产需要的受控复制子集为发布阻断。

#### US-032: 内容安全与权利治理

**用户故事**：作为制片人、审核员和发布运营，我希望所有输入素材、人物形象、声音和AI生成结果具备可验证的授权与安全结论，以便商业发行并在授权变化时及时阻断风险。

**验收条件**：
- [ ] **AC32.1 权利元数据**：上传或复制的图片、视频、音频、字体、Prompt参考、数据集和人物/声音样本记录来源、权利人、授权类型、用途、地域、有效期和证据引用。
- [ ] **AC32.2 生成前预检**：Prompt、参考素材、人物形象和声音在提交AI任务前执行适用的安全/授权规则；blocker不得绕过，warning需授权角色确认。
- [ ] **AC32.3 结果预检**：生成图片、视频和音频在采用或送审前保存安全扫描结果、规则版本和人工处置；扫描失败不能显示为通过。

- [ ] **AC32.5 同意与克隆**：人物肖像和声音克隆必须关联可验证同意；没有明确启用和授权时声音克隆入口不可用。
- [ ] **AC32.6 撤销与到期**：授权撤销、到期或法务冻结后，系统列出受影响资产、快照、待执行任务和发布计划，阻止新的生成/采用/发布并通知责任人。
- [ ] **AC32.7 申诉与豁免**：允许有权限角色提交证据申请复核；豁免具有范围、有效期、批准人和原因，不得全局永久跳过规则。
- [ ] **AC32.8 审计与最小披露**：所有安全与授权决定可追溯；普通成员只看到完成工作所需结论，不暴露敏感身份证明和凭据。

#### US-009: AI 图片生成

**用户故事**：作为分镜导演，我想要从分镜一键发起 AI 生图，以便高效生产分镜底图。

**领域归属**：[§3.5 AI 任务调度](../domain/contexts/05-ai-task-orchestration.md) - 聚合根 `AITask` (type=image) + 事件 `AITaskCompleted` → [§3.4 资产库](../domain/contexts/04-asset-library.md) 绑定候选。

**验收条件**：
- [ ] **AC9.1 任务提交**：从分镜生图时自动加载角色 / 场景 Prompt 至任务输入（不可手动修改分镜外内容）。
- [ ] **AC9.2 参考图支持**：支持图生图模式（上传多张参考图），单任务最多 4 张参考图。
- [ ] **AC9.3 模型选择**：可选择 AI 模型（仅 `status=active` 且 `modelType=image` 的 `ModelConfig`），默认按场景标签自动选默认模型。
- [ ] **AC9.4 批量提交**：支持选多个分镜批量生成，任务进入队列，队列按 FIFO 调度。
- [ ] **AC9.5 队列管理**：队列支持暂停、取消和重试。`queued` 可立即取消；`running` 取消时，Provider 支持中止则进入 `cancelling`，不支持则进入 `cancel_requested`，结果返回后不得自动采用；`unknown_result` 必须先对账，禁止直接重试。
- [ ] **AC9.6 进度展示**：实时显示生成进度（队列位置 / 执行中百分比 / 预估剩余时间），通过 SSE（Server-Sent Events）推送。
- [ ] **AC9.7 候选展示**：单次候选数量支持 1-4 张、默认 4 张，并受所选模型能力和预算约束；提交前显示实际数量与预计成本，结果支持缩略图和大图预览。
- [ ] **AC9.8 候选操作**：每张候选支持选择（绑定到分镜底图）、下载（PNG 原图）、删除（仅未选中的可删）。
- [ ] **AC9.9 参数记录**：每次生成记录 `prompt / model / seed / 参考图` 到 `image_tasks` 表，生成历史可查询。
- [ ] **AC9.10 成本估算**：显示单张图片成本估算、项目累计图片成本，预算超限时黄色 / 红色预警（默认阈值可在项目设置中调整）。
- [ ] **AC9.11 限流处理**：所选 Provider 返回限流或可重试的临时错误时，按模型策略退避重试；耗尽后返回稳定错误码、重试建议和成本处理结果，不暴露供应商私有错误结构。
- [ ] **AC9.12 状态机**：任务至少覆盖 `queued / running / cancelling / cancel_requested / completed / failed / cancelled / timed_out / unknown_result`；输入版本变化后结果标记 `stale`，不得自动采用。状态转换以 [§2.1 状态机](../domain/contexts/05-ai-task-orchestration.md) 为准。
- [ ] **AC9.13 幂等性**：相同 `Idempotency-Key` 的重复提交只创建一个任务；同一分镜可用不同 key 生成多个候选。Provider 回调通过 `providerRequestId` 去重。
- [ ] **AC9.14 重试上限**：`maxRetry` 默认 2 次，重试耗尽后任务进入 `failed` 终态。

**字段规范**：见 [§3.9 图片生成任务表单](#39-图片生成任务表单)。

**依赖**：US-005、US-007、US-008。

**优先级**：P0

**API 契约**：见 [§5.1.9 `POST /api/images/generate`](#519-post-apiimagesgenerate)、[§5.1.10 `GET /api/images/tasks/{id}`](#510-get-apiimagestasksid)。

**用户故事**：作为制片人/分镜导演，我想要创建、编辑、发布、复制和归档 Prompt 模板，以便为 AI 生成任务提供标准化、可复用、版本可追溯的 Prompt 输入。

**领域归属**：[§3.5 AI 任务调度](../domain/contexts/05-ai-task-orchestration.md) - 聚合根 `PromptTemplate` + 命令 `CreatePromptTemplate` / `UpdatePromptTemplate` / `PublishPromptTemplate` / `CreateNewPromptVersion` / `ArchivePromptTemplate` / `RestorePromptTemplate`。

**验收条件**：
- [ ] **AC-PM.1 创建模板**：支持创建 Prompt 模板，必填字段为名称（1-100 字符）、分类（`character_design | scene | storyboard | poster | script_analysis | custom`）、适用模型类型（`text | image | video | audio`）；可选字段为描述、场景标签（`sceneTags`）。创建后状态为 `draft`。
- [ ] **AC-PM.2 编辑模板**：仅 `draft` 状态可编辑 Prompt 正文（含 `{{variable}}` 变量占位符）和变量定义；已发布版本的 `content` 不可修改（依据 [§7.3 不变量](../domain/contexts/05-ai-task-orchestration.md)）。
- [ ] **AC-PM.3 变量校验**：Prompt 正文中的变量占位符必须与 `variables` 定义一一对应，发布前校验，不匹配时报错并列出缺失/多余变量。
- [ ] **AC-PM.4 发布模板**：`draft` 状态执行发布后状态变为 `published`，创建不可变快照；AI 任务调度引用 Prompt 时必须引用 `status = published` 的版本。
- [ ] **AC-PM.5 版本管理**：从已发布版本可通过 `CreateNewPromptVersion` 创建新草稿版本（新聚合实例，`previousVersionId` 链接旧版本），形成版本链；支持查看版本历史列表与版本间内容对比。
- [ ] **AC-PM.6 复制模板**：支持基于现有模板（任意状态）复制创建新模板，复制其 `content` / `variables` / `category` / `modelType` / `sceneTags`，新模板名称默认追加"_副本"后缀，状态为 `draft`，与原模板无版本链关系（通过 `CreatePromptTemplate` 实现）。
- [ ] **AC-PM.7 归档与恢复**：`published` 状态可归档（`archived`），归档后 AI 任务不可新引用（已有引用保留并提示失效）；`archived` 状态可恢复到 `published`（`RestorePromptTemplate`）。
- [ ] **AC-PM.8 作用域**：模板分全局模板（`projectId = null`，仅 admin 可创建/修改/发布）和项目级模板（受项目权限约束，`owner` / `admin` 可管理）。
- [ ] **AC-PM.9 列表与筛选**：Prompt 中心支持按分类、适用模型类型、场景标签、状态、作用域（全局/项目）筛选；支持按名称模糊搜索。
- [ ] **AC-PM.10 引用计数**：模板详情页显示被 AI 任务引用的次数（仅统计 `published` 版本的引用）。
- [ ] **AC-PM.11 乐观锁**：编辑保存使用 `version` 乐观锁，并发冲突时提示"模板已被他人修改，请刷新后重试"。
- [ ] **AC-PM.12 项目归档联动**：项目归档后（收到 `ProjectArchived` 事件），项目级 PromptTemplate 标记为只读，拒绝写命令；项目恢复后（`ProjectRestored`）解除只读（依据 [§1.6 不变量](../domain/contexts/05-ai-task-orchestration.md)）。

**依赖**：US-001（项目级模板依赖项目存在）；US-009 / US-011（AI 生成任务引用已发布模板）。

#### 2.13.5 事件订阅契约（开发实现指引）

智能助手 / 各消费上下文在订阅事件时，按以下契约实现：

| 项 | 规范 |
|----|------|
| 订阅方式 | 应用启动时通过 `EventBus.subscribe(eventName, handler)` 注册 |
| 幂等性 | 同一事件 ID 重复消费不产生副作用（用事件 ID + 读模型版本号去重） |
| 失败重试 | 消费失败自动重试 3 次（指数退避：1s/5s/30s），仍失败入死信队列 |
| 顺序保证 | 同一聚合的事件按发布顺序消费；不同聚合不保证全局顺序 |
| 事务边界 | 事件发布与聚合持久化在同一事务；消费方在独立事务中更新本地状态 |
| 死信处理 | 死信事件写入 `event_dlq` 表，告警通知，运维可手动重放 |

当前实现兼容映射：`episode_count → plannedEpisodeCount`、`due_date → dueDate`、`storage_path → storagePath`、`storage_mode → storageMode`；中文 `status` 和自由文本 `owner` 必须迁移为机器状态和认证主体，不得继续作为长期 API 契约。当前后端 `type=short_drama/mv/ad/film` 与产品结构类型冲突，迁移时不得覆盖 `single/series`，内容制品类型在 V1 固定为动态漫剧或另设 `contentType`。

**联动逻辑**：
- `type=series` 时显示“计划集数”输入；创建仍只初始化第 1 集，用户显式确认后才能批量建立其余 Episode。
- `storageMode=existing` 时显示目录、权限和冲突预检；`managed` 不要求用户填写路径。

## 四、状态机索引

本节汇总 DDD 各上下文中关键聚合的状态机，作为 US-001 到 US-021 状态字段的**权威定义**。所有 UI 状态显示、状态过滤、状态转换按钮必须与下表一致。

### 4.1 Project（项目管控 §3.1）

**状态**：`active` / `archived`

**转换规则**：

| 起始状态 | 命令 | 目标状态 | 前置条件 |
|---------|------|---------|---------|
| 不存在 | `CreateProject` | `active` | — |
| `active` | `ArchiveProject` | `archived` | 所有关联 PipelineRun 终态、剧集无进行中审核、FinalVideo 无 packaging、PublishPlan 无 executing |
| `archived` | `RestoreProject` | `active` | — |
| `active` | `SoftDeleteProject` | (软删除) | — |

### 4.2 Episode（项目管控 §3.1）

**状态**：`active` / `archived`

**联动**：项目 `archived` 时，剧集自动 `archived`；项目 `active` 时剧集不会自动恢复。

### 4.3 Script（剧本创作 §3.2）

**状态**：`draft` / `analyzing` / `analyzed` / `published`

**转换规则**：

| 起始状态 | 命令 | 目标状态 | 备注 |
|---------|------|---------|------|
| 不存在 | `CreateScript` / `ImportScript` | `draft` | — |
| `draft` / `analyzed` | `AnalyzeScript` | `analyzing` | — |
| `analyzing` | `CompleteAnalysis` | `analyzed` | analysisRevision +1 |
| `analyzing` | `FailAnalysis` | `draft` | — |

## 五、API 契约

### 5.1 API 设计原则

- 路径以 `/api/` 为前缀，**不使用**版本号段（兼容性通过字段和路径兼容实现）。
- 资源命名使用复数名词；URL 层级不超过 3 级。
- 使用 HTTP 标准方法（GET/POST/PUT/PATCH/DELETE）。
- 统一响应结构：成功为 `{ "data": {}, "meta": {}, "traceId": "trc_..." }`；失败为 `{ "error": { "code": "stable_string_code", "message": "...", "details": {}, "retryable": false, "traceId": "trc_...", "legacyCode": 1001 } }`。`legacyCode`仅兼容期可选返回。
- 错误码见 [§5.4](#54-错误码定义)。
- 所有请求/响应均为 JSON 格式，时间字段为 ISO 8601 字符串。
- 鉴权见 [§5.2](#52-认证与授权)。

### 5.2 认证与授权

- JWT Token 认证：`Authorization: Bearer {token}`。
- Token 过期：24 小时；刷新 Token 有效期 7 天。
- 除登录 / 注册 / 健康检查外，所有 API 都需要验证 Token。
- 鉴权模式 `AUTH_MODE`：`required`（生产）/ `optional`（开发）。
- 资源级 RBAC：项目级可见性 + 资源所有权二次校验。

### 5.3 统一响应结构

> 本节的权威结构以 [统一错误与 HTTP 响应契约](../domain/08-error-contract.md) 为准。新接口不得返回数字类型 `code`；现有 `{code,message,data}` 仅作为待迁移旧协议。

**成功**：
```json
{
  "data": { "id": "..." },
  "meta": {},
  "traceId": "trc_..."
}
```

**失败**：
```json
{
  "error": {
    "code": "command_validation_error",
    "message": "项目名称格式不正确",
    "details": {
      "field": "name",
      "reason": "项目名称 1-100 字符"
    },
    "retryable": false,
    "traceId": "trc_...",
    "legacyCode": 1001
  }
}
```

**分页列表**：
```json
{
  "data": {
    "items": [],
    "total": 100,
    "page": 1,
    "pageSize": 20,
    "totalPages": 5
  },
  "meta": {},
  "traceId": "trc_..."
}
```

### 5.4 旧数字错误码迁移表（只读兼容）

> 下表仅用于识别旧消费者和生成可选 `legacyCode`，不得作为新开发的机器错误码。新错误码、HTTP 与 retryable 语义见 [统一错误与 HTTP 响应契约](../domain/08-error-contract.md)。

错误响应以[统一错误与 HTTP 响应契约](../domain/08-error-contract.md)为唯一权威：`error.code`为稳定小写snake_case字符串；HTTP表达协议语义；数字只可在兼容期放入可选`legacyCode`。成功响应不得再用`code: 0`表示。

| error.code | HTTP | retryable | 说明 | 示例场景 |
|------|------:|:------:|------|---------|
| `command_validation_error` | 422 | false | 字段或命令校验失败 | 字段缺失、格式错误 |
| `authentication_required` | 401 | false | 未认证或会话失效 | Token 无效/过期 |
| `permission_denied` | 403 | false | 权限不足 | 无项目访问权限 |
| `aggregate_not_found` | 404 | false | 资源不存在或不可见 | 项目 ID 不存在 |
| `invalid_state_transition` | 409 | false | 状态转换非法 | 在终态执行start |
| `aggregate_version_conflict` | 409 | true | 乐观锁冲突 | 并发保存旧版本 |
| `aggregate_invariant_violated` | 409 | false | 业务不变量违反 | 归档时仍有活动审核 |
| `dependency_conflict` | 409 | false | 引用关系阻断 | 删除仍被引用的资产 |
| `budget_exceeded` | 402 | false | 预算硬上限 | 项目预算不足 |
| `quota_exceeded` | 429 | true | 配额耗尽 | 项目或Provider配额不足 |
| `rate_limit_exceeded` | 429 | true | 请求频率超限 | 返回retryAfterMs |
| `deadline_exceeded` | 504 | true | 外部调用超时 | Provider超时 |
| `provider_unavailable` | 503 | true | 外部Provider不可用 | AI或发布渠道故障 |
| `internal_error` | 500 | false | 未分类内部错误 | 通过traceId排查 |

本文后续历史API示例中的旧`{code,message,data}`只用于识别待迁移接口，不得作为新接口或验收依据；新验收统一使用成功`{data,meta,traceId}`和失败`{error:{code,message,details,retryable,traceId,legacyCode?}}`。

### 5.5 API 性能要求

| API 类型 | 响应时间 P95 | 并发要求 | 备注 |
|---------|------------|---------|------|
| 数据查询 API | ≤ 500ms | 50 并发 | 单表查询 |
| 数据写入 API | ≤ 1s | 20 并发 | 含事务 |

本节汇总跨 US 的关键业务规则，避免在每个 US 中重复定义。

| 规则编号 | 规则 | 涉及 US | 触发时机 | 错误处理 |
|---------|------|---------|---------|---------|
| BR-001 | 项目归档前所有关联 PipelineRun 必须处于终态 | US-001、US-002 | ArchiveProject | 返回 `INVARIANT_VIOLATION`，列出未完成 Run |

| BR-003 | 项目归档前 FinalVideo 不可处于 packaging | US-002 | ArchiveProject | 同上 |
| BR-004 | 项目归档前 PublishPlan 不可处于 executing | US-002 | ArchiveProject | 同上 |
| BR-005 | 剧集删除前必须无关联分镜板和成片 | US-002 | SoftDeleteEpisode | 返回 `CONFLICT_ERROR`，列出冲突资源 |
| BR-006 | 一个项目必须有且只有一个 owner | US-001 | AddMember、TransferOwnership | 已有 owner 时禁止直接添加新 owner |
| BR-007 | owner 不可被 RemoveMember 移除 | US-001 | RemoveMember | 返回 `INVARIANT_VIOLATION` |
| BR-008 | 已发布剧本文档不可修改，只能通过 CreateNewVersion 创建新版本 | US-003 | UpdateScript | 状态转换错误 |
| BR-009 | 剧本 analyzing 状态不可编辑或删除 | US-003 | UpdateScript、SoftDeleteScript | 状态转换错误 |
| BR-010 | AI 剧本分析重试最多 3 次，指数退避（10s/30s/60s） | US-004 | FailAnalysis 重试 | 超过 3 次后进入 `draft` 终态 |

| BR-021 | FinalVideo 仅由 completed RenderJob 创建；渲染快照内所有 sourceShotIds 必须 approved | US-015、US-017 | RenderCompleted/CreateFinalVideo | `INVARIANT_VIOLATION` 列出无效渲染或未通过分镜 |

## 八、前端验收标准

### 8.1 优先级定义

- **P0**：上线阻断。白屏、核心功能不可用、数据串会话、保存失败、误删、导出不可用。
- **P1**：重要体验问题。布局错位、空状态缺失、筛选不准、错误提示不清楚、移动端难用。
- **P2**：体验优化。动效、微文案、视觉细节、非核心兼容性。

### 8.2 通用验收

**视觉与布局（P0）**：
- 页面不能出现内容重叠、主要按钮不可见、输入框遮挡操作区。
- 图片和视频必须按原比例展示，不允许拉伸变形。
- 320px 到 1920px 宽度下核心页面可用，不出现破坏性横向滚动。
- 文本不能撑破按钮、卡片、菜单和表格单元格。

**交互（P0）**：
- 所有可点击按钮必须有有效结果，不能点击无反应。
- 保存、删除、导出、生成、上传必须有成功或失败反馈（Toast / 通知中心）。
- 请求中的按钮要防重复提交（loading + disabled）。
- 删除、移除、归档等危险操作必须二次确认（弹窗 + 二次输入"确认删除"）。

**功能逻辑（P0）**：
- 查询、提交、保存、删除、导出接口调用成功。
- 接口失败或网络失败时页面不白屏，展示明确错误（含错误码 + 建议操作）。
- 会话、图片、视频、项目、资产必须绑定正确归属，不能串数据（依据 [§5.2 资源级 RBAC](#52-认证与授权)）。

**工程（P0）**：
- `npm run build` 必须通过。
- 后端相关改动必须通过 `npm test`。
- 不能留下导致构建失败的类型错误。
- 不直接渲染用户输入的原生 HTML。

### 8.3 专项验收

**对话会话（P0）**：
- 新建会话后可以发送消息。
- 一个会话正在生成时，新建其他会话不能中断原任务。
- 停止生成、重新生成入口可用。
- 点击历史会话后，消息展示区显示对应会话内容。

**图片生成（P0）**：
- 支持多张图片附件上传和预览。
- 生成结果绑定当前会话和当前项目。
- 历史会话中的图片只显示在所属会话下。
- 图片详情页能新标签页打开，支持查看、下载、复制、收藏、删除。
- Provider限流错误要提示清楚，展示可重试时间和任务状态，不能无限 loading。

**视频生成（P0）**：
- 视频生成任务绑定当前会话和项目。
- 视频结果可播放、打开详情、下载。
- 分镜底图资产可以直接带入图生视频。
- 任务队列支持暂停、取消、重试（依据 [§4.7 AITask 状态机](#47-aitaskai-任务调度-35)）。

**项目工作台（P0）**：
- 项目首页、团队、剧集、问题、里程碑、剧本、分镜、剪辑、审核、任务、资产、交付工作页可正常切换。
- 新增、更新、删除操作调用接口成功。
- 项目不存在时要退出坏 ID，不能持续报 `project not found`。
- 归档 / 删除二次确认依据 [§8.2 危险操作规范](#82-通用验收)。

**资产库（P0）**：
- 支持图片、视频、角色、场景、风格、Prompt 模板、项目资料、分镜底图分类。
- 资产可新增、删除、收藏、取消收藏。
- 图片和视频资产可作为生成输入源复用。
- 角色和场景资产可绑定到分镜。
- usageCount>0 时软删除按钮置灰 + 提示"被 N 个分镜引用，不可删除"。

**状态机可视化（P0）**：
- 详情页显示当前状态及状态来源（如"因 X 事件触发进入 ready"）。
- 状态转换按钮根据当前状态动态显示（如 `approved` 状态不显示"提交审核"）。
- 非法状态转换时按钮置灰 + Tooltip 说明"当前状态不允许此操作"。

**交付导出（P0）**：
- 剧本文档 TXT、分镜表 CSV、剪辑清单 CSV、项目清单 JSON 可导出。
- CSV 中文不乱码（UTF-8 BOM）。
- 导出过程显示进度，完成后浏览器自动下载。

### 8.4 验收命令

后端：
```bat
cd backend
npm test
```

前端：
```bat
cd frontend
npm run build
npm run test:e2e
```

| 关系 | 类型 | 说明 |

| Project → Episode | 1:N | 一个项目包含多个剧集 |

| Episode → ScriptDocument | 1:N | 一个剧集包含多个剧本文档 |
| Episode → Storyboard | 1:N | 一个剧集包含多个分镜板 |
| Storyboard → Shot | 1:N | 一个分镜板包含多个分镜 |
| Storyboard → Character | N:M | 一个分镜可关联多个角色 |
| Storyboard → Scene | N:1 | 一个分镜关联一个场景 |
| Storyboard → Prop | N:M | 一个分镜可关联多个道具 |

| Shot → VideoTask | 1:1 | 一个分镜对应一个视频任务 |

### 9.4 数据库设计原则

- 主键使用 TEXT（系统生成的字符串 ID，不使用自增整数）。
- 软删除优先：`deleted_at` 字段，物理删除走管理接口。
- 高频查询字段建立索引。
- 复合查询建立复合索引。
- 跨表写入使用事务包裹（`db.exec("BEGIN")` / `db.exec("COMMIT")`）。
- 乐观锁：`version` 字段，每次更新 +1，防止并发覆盖。
