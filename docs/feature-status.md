# 功能状态基线

> **基线日期**：2026-07-28
> **状态**：待逐项代码核验
> **规则**：本文件是“当前真实能力和对外承诺”的唯一权威来源。未经代码、接口和验收用例三方证据确认，不得标记为“已完成”。

## 1. 状态定义

| 状态 | 含义 | 最低证据要求 |
|---|---|---|
| 已完成 | 可在受支持环境稳定使用 | 代码入口 + API/存储 + 自动化验收全部通过 |
| 部分完成 | 主路径可用，但存在明确缺口 | 已列出可用范围、缺口和临时限制 |
| 仅原型 | 只有界面或演示数据 | 不得对外承诺生产可用 |
| 仅设计 | 只有需求/DDD/API 设计 | 不得计入发布范围 |
| 未核验 | 尚未完成代码—文档对照 | 默认状态，不等同于已完成 |

## 3. 完成状态变更流程

1. 负责人提供代码路径、API 路由、数据库迁移和验收用例编号。
2. 自动化测试通过，且异常、权限、幂等和恢复路径有证据。
3. 产品、开发、测试共同确认真实边界和已知限制。
4. 更新本表及变更日志；状态变更必须通过代码评审。

## 4. 禁止事项

- 不得用页面存在、按钮可点击或 mock 数据展示代替功能完成。
- 不得把“仅设计”“后期实现”“规划中”描述为可发布能力。
- 不得在模块指南、README 或发布说明中绕过本文件单独声明完成状态。
